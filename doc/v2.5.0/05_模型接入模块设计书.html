1 先行验证与运行依赖

证据见 OMP 先行验证。固定 OMP commit b07a1c146d0d12cfc855a2c65d52f892ef319040；直接依赖 @oh-my-pi/pi-ai、pi-tui、pi-catalog、pi-utils 18.8.7，MIT。Bun 1.3.14 执行其原始 TypeScript、bun:sqlite/FFI 和预编译 pi-natives；不安装 coding-agent，不重写 Rust、不引入 Python。浏览器会话依赖 puppeteer-core 25.3.0，不下载自带浏览器，不关闭 TLS/沙箱。

沿用唯一 npm package-lock.json，npm ci --ignore-scripts；Bun 只是运行时。Node 22.23.1 与原 openai 7.32.0、jose 6.2.12、smol-toml 1.9.1、string-width 8.3.0 保留。tsc 同时检查新增静态类型；构建输出仍位于 runtime/model-access-build。新增 Bun 入口与原 Node 入口分别运行，P1/P2 不依赖它们。

{"v":2,"id":"catalog_1","op":"models","provider":"google-antigravity","account_id":1}

原 v1 protocol.json 与 Node serve 的 api/chatgpt 字段和语义保持。Bun CLI 提供 menu/status/providers/serve/unlock；登录与退出通过 TTY 菜单进行。公开 JSONL 不开放登录回调。两入口共用锁，禁止同时持有配置。跨语言调用只依赖 JSONL；不调用 P1/P2 API 或私有库/表，也不修改 EvidenceExtractor/JevDecisionProvider/FrameworkClient。

3 配置与 OMP 凭据端口

原配置字段保持；增加 omp_max_requests=0、omp_browser_path=""，旧配置缺项按零/空兼容。模板不填容量、路径或秘密。原 state_json 增加可选 omp：next_id（单调正整数）、credentials（id/provider/credential/disabledCause）、cache（key/value/expires）、budgets（按 provider:account_id 的原 Budget 结构）。凭据按上游 API key/OAuth 类型验证（注册表 ID 允许点号、禁止斜杠）；只有合法配置才能载入。失效行保留本地 ID 与稳定原因码，注销直接移除秘密，不回收 ID；预算不随退出清除。

TomlCredentialStore 实现 list/update/replace/upsert/delete、tryUpdate/tryDisableIfMatches 和 cache 端口。CAS expectedData 按上游 serializeCredential 去掉 type 后比较；对 API key 仅比较 key/source。upsert OAuth 使用上游 resolveCredentialIdentityKey，避免同一身份重复；API key 登录按上游 upsert 语义执行；入口别名在存储边界统一到 storeCredentialsAs。list 只返回活动行的深拷贝。同步写入成功后才返回，不向调用者泄露原始错误/disabledCause；所有上游日志关闭。

saveSync 使用现有 canonical config/config.toml、0600、无符号链接、16MiB 包络、排他 owner 锁、原配置哈希、区外语义/原字节保持、临时文件 fsync/rename/目录 fsync。save 直接调用同一同步实现，避免异步与同步写交错。冲突/写失败 poison 实例，后续操作拒绝。OMP AuthStorage 通过端口构造，不调用默认 SQLite create，不读取既有账户目录。模型目录缓存隔离于忽略的 runtime/model-access-omp，按 provider+本地句柄分区且注销清理对应缓存；不保存令牌。PI_CODING_AGENT_DIR 由启动器显式指向独立私有运行目录，禁止落到用户原 ~/.omp。

4 完整登录、刷新及浏览器回调

getOAuthProviders 提供全部入口及 storeCredentialsAs；菜单直接使用 OAuthSelectorComponent。AuthStorage.oauth.login(provider, controller) 完成供应商逻辑；controller 的 onAuth→LoginDialog.showAuth，onProgress→showProgress，onPrompt→showPrompt（未声明 secret 时也默认隐藏认证输入），onManualCodeInput→showManualInput，onBrowserSession→独立浏览器捕获。Ollama 的显式空 Key 本地模式登记本地连接标记以供选择，不启动本地模型服务。登录 AbortSignal 同时绑定 Esc、全局中断及配置 login_timeout_seconds，finally 关闭自身监听/对话。取消后不允许提交迟到凭据。

登录网址由原版对话在 TTY 显示，并尝试系统浏览器打开；Ubuntu 缺图形环境时保留可复制网址，按上游手动回填/设备码流程操作。浏览器会话采用 upstream browser-session.ts 的独立 profile 与 CDP Network.getCookies，仅为请求域读取所需名称，并返回首个匹配值；使用配置浏览器，保持 sandbox/TLS。取消/超时关闭自己创建的浏览器，最终删除自己的 profile；不扫描其他窗口/账号，浏览器错误只映射稳定码。

请求按本地行 ID 查找明确账户。API Key 直接读取该行；OAuth 使用 auth.oauth.accessById(provider,id,{signal})，不使用会自动轮换或读取环境的 keys.get。访问成功后从刷新后的对应行构造 getOAuthApiKey，保留 Antigravity projectId、Codex accountId、Anthropic组织等上游所需内部元信息；这些不进入 DTO。上游 single-flight 与 ConfigStore 独占写锁共同保护轮换。失效或刷新失败映射 AUTH_REQUIRED/AUTH_REFRESH_FAILED，不转其他账户。

退出确认后 credentials.removeById 只删除选中行；若上游采用失效标记，适配层删除该行秘密。远端撤销没有通用保证，返回 remote_revocation_confirmed=false。原动态 ChatGPT adapters/oauth.ts 与其单账号状态、计划 scope、JWT 签名/nonce/client_id 等检查及撤销逻辑保持，旧菜单单独进入。

5 模型发现与程序调用

pi-catalog PROVIDER_DESCRIPTORS 用于常规模型管理；getProviderDefinition.prepareModelDiscovery 处理供应商 Key 格式。openai-codex、google-antigravity、google-gemini-cli 使用对应 ModelManagerOptions，resolveAccounts 只返回显式行，不能 union 其他账户。模型缓存以本地账号分区。只暴露 chat 模型，工具凭据无模型时返回 PROVIDER_NOT_TEXT。source=provider/cache/bundled/models.dev 作为来源，不能将 fallback 目录标为账号已验证。不得选中目录中不存在的模型。

使用 pi-ai stream，context 仅私有 systemPrompt、单条 user 文本、无工具。显式 apiKey、credentialId/oauthIdentity、AbortSignal；storeResponses=false、statefulResponses=false、codexSseMaxAttempts=1；不提供 providerSessionState/sessionId，因此 Codex 不创建 WebSocket 会话。禁用 agent loop/工具执行；不传自动账号解析器。providerRetryWait 立即中止并报错；包装 fetch 在 HTTP 拒绝、传输错误或流错误时中止本次生成，防止内部重试重复消耗。绝不自动二次调用 stream 或改模型。对原版自有非-fetch 传输仍传取消/重试钩子，并单独记录现场验证边界。

adapters/omp-stream-guard.ts 在原版解析前只观察有界 SSE 元数据：累计响应包络不得超过 max_line_bytes；OpenAI/Codex response.completed、completions finish_reason、Anthropic stop_reason、Google finishReason 提供完结证据；拒绝字段立即 RESPONSE_REFUSED，缺失明确终态不得成功。支持 SSE 多行/分块/UTF-8 与最后未空行，正文解析仍完全复用上游。其他协议保留其原版终态检查并单独记录现场边界。逐事件检查文本及思考的 UTF-8 输出上限，等待 done 成功终态；stop/受支持正常结束才可返回，error/aborted/length/toolUse/refusal/空文本拒绝。用量只返回有限非负 input/output/total 数值；不返回原错误文本/stack/URL或任意原始包络。供应商失败 HTTP 状态映射 401/403/429/5xx；请求已开始但终态无法确认时 delivery_unknown=true。生成尝试在上游发送前持久记录；正数本地限额才检查耗尽，失败不释放。不限次数保留有限最近ID去重；暂停账户不会自动轮换。输入+私有Prompt共同限额，单次正数边界与时钟检查保持。

6 原版交互组件的装配

initThemeSync 后创建 TUI(new ProcessTerminal())。首页/账号/确认使用上游 SelectList；登录用 OAuthSelectorComponent 和 LoginDialogComponent；模型用 ModelPickerComponent，以最小 ModelBrowserSource/Registry 宿主适配器提供已选账户目录。宿主不接入 coding-agent roles、subagent 或工具。搜索/滚动/边框/宽字符由原版组件处理；长状态与生成结果用原版 ScrollView，随终端高度调整视口，方向键/PageUp/PageDown/Home/End 滚动，Enter/Esc 返回。

首页包含完整登录、选账户与模型、查看预算、显式调用测试、设置推理边界、退出账户、旧 API/官方动态 ChatGPT 菜单与退出。会话选择只保存在内存；显式测试先确认消耗再收输入，结果只在终端显示。边界设置逐项收集并校验用户输入，确认后整体保存；不自动生成容量。Ctrl+C/SIGTERM/EOF 取消当前操作，finally 停止 TUI、暂停 stdin、关闭 AuthStorage 并释放配置锁。退出当前层 Esc 返回，首页 Esc 退出；取消任何确认不执行副作用。

旧 Node 命令 menu 在取得配置锁之前启动 Bun omp-cli；传递绝对配置路径、清理供应商密钥/代理账单环境覆盖；退出码保持。legacy-menu 继续原菜单及官方 CLI 手动管理入口。直接 Bun 命令使用相同隔离启动配置。入口使用 pi-utils.postmortem.register 注册宿主清理：取消统一信号、等候当前操作 finally 关闭 AuthStorage/ConfigStore 后才允许上游硬退出。菜单订阅该统一取消信号；正常退出注销 cleanup。serve 在 SIGINT/SIGTERM 时销毁自有 stdin 读流以解除空闲读取，并释放配置锁；取消时不输出成功。serve stdout 仅 JSON；TUI 与机器模式分别入口，不能混用。

7 异常、验收与部署

ConfigStore 冲突→CONFIG_WRITE_CONFLICT/CONFIG_PERSIST_FAILED；运行时缺失→OMP_RUNTIME_REQUIRED；无账户→AUTH_REQUIRED；无文本能力→PROVIDER_NOT_TEXT；目录未包含模型→MODEL_NOT_AVAILABLE；限额缺失→LIMITS_REQUIRED/CHANNEL_DISABLED；超时/断流→DELIVERY_UNKNOWN；429→RATE_LIMITED 并暂停该账户。错误不输出原始上游 message/stack，status 不返回身份字段。登录错误显示稳定码与重试/配置说明，保留旧连接。

覆盖 T5-11～T5-15：注册表82入口对照、别名、原版组件事件/掩码/窄屏、受控 OAuth/设备码/浏览器会话回调、重启和一次并发刷新、行级注销、外部配置冲突、旧通道回归、真实原版 provider 的合成 SSE 成功/拒绝/断流/超时/429 无生成重试、独立 JSONL 与真实 PTY 退出恢复。检查 Go layout、TS AST 静态导入白名单、类型、两运行时测试、公开索引/可达历史、HTML 图/配对/桌面与窄屏。CI 固定 Bun，npm 安装禁用脚本，测试无真实账号。

部署只安装依赖/构建并准备兼容字段，不启动后台模型 worker，不执行真实登录或生成。用户随后运行菜单登录三家并分别完成 T5-16，记录账户现场结果；全部注册入口存在不等于82家账户均验收。旧 P3 未提交工作与私有配置原有值保留。

10 默认不限次数的实现（v2.5.0）

对应S5-004/T5-17/18。原字段api_max_requests、chatgpt_max_requests、omp_max_requests的0统一表示unlimited，正数表示windowed。budget_window_seconds=0仅在所用通道次数不限时允许，正数上限必须配正数窗口；原字段缺省兼容emptySettings的0。enabled仍独立控制生成。旧版0曾表示禁用，部署本版后明确按新语义解释；现有正数设置不自动改写。

代码执行设计
application/request-budget.ts共享本地策略：budgetStatus显示mode、limit（不限为null）、window_seconds；reserveBudget检查时钟及重复ID，只有max>0才比较count。window>0且到期才重置。不限次数只保留最近256个ID（技术内存界限，不是请求次数额度），count为累计尝试统计；有限额模式保留窗口内所有ID。正数计数接近JS最大安全整数时饱和，不把统计溢出变为停机条件。长期业务幂等仍由调用者承担。
application/service.ts 与 omp-service.ts原v1/v2请求契约保持，调用前走共享预占并持久写入。去掉0触发CHANNEL_DISABLED与无限模式的正窗口要求；status增加local_budget策略摘要。OMP发现目录前仍拒绝近期重复ID；HTTP429/订阅计划耗尽的原暂停逻辑保持。不增加重试、换账户或收费渠道回退。
config/store.ts / omp-state.ts0仍为合法默认值；Budget原字段不变。校验count为非负安全整数且count大于等于ids.length，ids唯一且格式有效；兼容旧count等于ids长度。窗口无过期的不限模式可安全重新打开，不因最近ID截断使状态无效；凭据、锁和原子写保持。
entrypoints/omp-menu.ts / menu.ts显示中文“无限制（本地）”；预算窗口0标为不重置统计。推理边界输入对预算字段允许0，空输入保持当前值；时间/字节字段仍需正数。正数次数+零窗口保存前拒绝。设置不发送模型请求。旧菜单预算视图同义，错误帮助不再要求填正数次数限额。
config模板 / README / 测试模板预算字段仍0并注明不限次数；不引入巨额伪上限。Node与Bun测试覆盖0/0、正数上限、有限额窗口缺失、重启、去重、无界次数但有界存储、私有配置原字段保留、菜单输入与429。纯确定性策略属于已定稿预算方法细化，不需额外真实账户调用。

无预算上限只针对Factorforge模型接入本地次数。P1/P2风险政策、交易准入、JEV既有共享供应商池及单次资源限制不因此取消。本模块保持私有TOML与公开JSONL边界，既有固定OMP代码无需修改。
