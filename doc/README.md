## 文档边界

式样书使用自然语言说明功能、效果、边界和验收条件。设计书只针对同层同名式样书，说明实现这些要求需要的代码结构、数据、接口、算法、事务和测试。开发规划只记录大阶段、阶段产出和完成条件，不承载需求、算法或接口真源。

每个发布版本放在独立目录。后续修改先确定目标版本；历史目录不得覆盖为新版。版本号、变更原因、影响需求、验证结果和未决项随版本登记。Markdown 是正文真源，Word 从同一正文生成；两种格式内容必须一致。接口版本与文档版本分别管理，不能仅因文档升级就认为旧接口已兼容新架构。

三段版本和 PR 合并规则以[贡献与版本规则](../CONTRIBUTING.md)为准，当前版本由根目录 VERSION 指定，[发布登记](releases.json)记录对应目录。整体框架变更增加主版本，式样变更增加次版本，仅设计或设计与代码共同变更增加修订版本；仅代码变更保留版本，在 GitHub 合并记录中记载。

## 历史迁移

原始概念需求归入 v0.1；未带版本后缀的两份旧式样书/规划书，其正文注明为1.0，归入 v1.0；其余按文件所示版本归档。配图分别保存在对应版本的 assets 中，旧 OpenAPI 放在 v1.0/api 中。历史正文未改写，设计书指向仓库外层资源的相对链接增加了一层父目录；修改链接的 Markdown 原始字节另存在对应目录的 .originals 中。[版本归档清单](版本归档清单.json)记录原始及归档 SHA-256。

现有根目录 contracts 是 v1.1 接口资产，保留供历史验证，不能作为 v2.0 接口实现依据。doc 下隐藏的旧构建工具保留为历史工具，除更新后的 v1.1审计外不直接重跑；v2.0 文档生成及校验工具独立放在 .v20-build。此索引仅管理文档；没有实施交易、开户、部署或公开发布。
