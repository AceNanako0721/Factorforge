## 1 结构

### 1.1 运行时与依赖

- 语言为 TypeScript，构建产物在 `runtime/model-access-build`（`npm run build`：`tsc` 编译后，在产物目录建立 `package.json` 和指向依赖的 `node_modules` 链接）。
- 多供应商通道使用 Bun 运行，依赖固定版本的 oh-my-pi 包：`@oh-my-pi/pi-ai`（登录注册表、认证存储、推理流）、`@oh-my-pi/pi-catalog`（模型目录）、`@oh-my-pi/pi-tui`（终端组件）、`@oh-my-pi/pi-utils`。浏览器会话登录用 `puppeteer-core`。
- 兼容通道使用 Node 运行，依赖 `openai`（Responses API）、`jose`（ID 令牌校验）、`smol-toml`、`string-width`。
- 从上游改写的源文件（`browser-session.ts`、`fuzzy.ts`、`menu-selection.ts`）在文件头注明来源提交和 MIT 许可，完整许可见仓库根目录的 `THIRD_PARTY_NOTICES.md`。

## 2 私有配置

### 2.1 配置块与读取（`ConfigStore`）

配置只能是名为 `config/config.toml` 的文件，否则返回 `CANONICAL_CONFIG_REQUIRED`。P5 的设置是文件最后一段，夹在 `# BEGIN FACTORFORGE MODEL ACCESS` 与 `# END FACTORFORGE MODEL ACCESS` 之间的 `[model_access]` 表；两行各只能出现一次，结束行之后不能再有内容。

**读取私有文件（`readPrivate`）**：路径上任何一级是符号链接都拒绝（`PRIVATE_PATH_INVALID`）；以不跟随链接方式打开，必须是普通文件、属于当前用户、不允许组和其他用户的任何权限，大小不超过上限（配置 16 MiB），否则返回 `PRIVATE_FILE_INVALID`。

**打开（`ConfigStore.open`）**：

1. 校验配置文件。
2. 在配置目录以独占方式新建锁文件 `.model-access.lock`（0600），写入 {所有者随机编号, 进程号, 主机名}。已存在时返回 `CONFIG_BUSY`。
3. 取得锁之后才读取配置内容并解析设置（这样读到的令牌一定是最新版本）。
4. `state_json` 为空时新建状态并立即保存。

读取配置或保存初始状态失败时，只删除自己建的锁（写入锁内容本身失败时，锁会留下，需要用 `unlock` 清理）。

**写入（`saveSync`）**：

1. 写入前比较磁盘上的配置与本进程读到的版本（SHA-256）。不同说明有外部修改，返回 `CONFIG_WRITE_CONFLICT`。
2. 只替换 P5 的配置块；替换后解析整个 TOML，确认块外的内容完全没变。
3. 写到同目录的临时文件（0600，fsync），再比较一次磁盘版本，然后原子改名覆盖，并 fsync 目录。
4. 写入中途失败时，进程标记为不可用：之后的登录、目录、生成和多供应商的状态查询都返回 `CONFIG_PERSIST_FAILED`，不再使用可能已经过期的刷新令牌。

所有写入都走这一个同步函数，以免令牌轮换与其他保存交错。

**解锁（`unlock`）**：锁文件的主机名必须是本机，进程号必须不存在，否则拒绝（`LOCK_REQUIRES_REVIEW` 或 `CONFIG_BUSY`）。

`tools/init-model-access` 在配置中缺少 P5 配置块时，从 `config/config.example.toml` 追加空模板；已有配置块时只补上两个官方程序路径字段，其他字节一律保留。其余后来加入的字段由 `ConfigStore` 在读取时补默认值、首次保存时写入。

### 2.2 设置字段

所有字段都必须存在且类型正确，数字必须是非负安全整数，不允许未知字段，否则返回 `MODEL_CONFIG_INVALID`。旧配置缺少后来加入的字段（两个官方程序路径、三个次数上限、预算窗口、浏览器路径）时，按空值或 0 读入，首次保存时写入。

**开关与边界**：

- `enabled`：生成开关。关闭时生成返回 `MODULE_DISABLED`；登录和查看状态不受影响。多供应商通道读取目录也不受影响；兼容通道读取目录与生成一样要求打开开关和全部边界。
- `timeout_seconds`：目录发现、令牌刷新和单次生成的时限；生成时必须为正。
- `login_timeout_seconds`：登录的时限，登录时必须为正。多供应商通道限制整个登录；兼容通道从显示授权网址起限制等待回调的时间。
- `max_input_bytes`：输入文本与系统提示词合计的字节上限，超过返回 `INPUT_LIMIT_EXCEEDED`；同时是提示词文件的大小上限。
- `max_output_bytes`：输出的字节上限。多供应商通道计入文本与思考文本；兼容通道只计入输出文本。
- `max_line_bytes`：JSONL 请求行的上限、多供应商通道成功生成的响应行上限，也是一次供应商响应的总字节上限。

生成时这四个数都必须为正，否则返回 `LIMITS_REQUIRED`；毫秒换算超出计时器范围时返回 `LIMITS_INVALID`。

**本地预算**（第 4 章）：

- `api_max_requests`、`chatgpt_max_requests`：兼容通道的 API Key 通道和 ChatGPT 通道的次数上限。
- `omp_max_requests`：多供应商通道每个账户的次数上限。
- `budget_window_seconds`：预算窗口，三者共用。

**兼容通道**：

- `api_base_url`、`api_key`：Responses API 的根地址与 API Key。地址必须是 `https`，不含用户信息、查询或片段。
- `claude_cli_path`、`antigravity_cli_path`：官方命令行程序的绝对路径（第 6.3 节）。

**多供应商通道**：

- `omp_browser_path`：Chromium 或 Chrome 的绝对路径，只有浏览器会话登录需要。

**提示词**：

- `prompt_file`：私有提示词文件，路径相对仓库根目录，必须在 `prompts/` 之下，不能是 `prompts.example.json`。文件是 JSON，`instructions` 字段为字符串，作为系统提示词。为空时不使用系统提示词。读取失败返回 `PRIVATE_PROMPT_INVALID`。

**状态**：

- `state_json`：由程序维护的状态 JSON，不能手工编辑。

示例（中性值）：

```toml
# BEGIN FACTORFORGE MODEL ACCESS
[model_access]
enabled = true
api_base_url = ""
api_key = ""
prompt_file = "prompts/example.json"
timeout_seconds = 120
login_timeout_seconds = 600
max_input_bytes = 262144
max_output_bytes = 65536
max_line_bytes = 1048576
budget_window_seconds = 0
api_max_requests = 0
chatgpt_max_requests = 0
omp_max_requests = 0
claude_cli_path = ""
antigravity_cli_path = ""
omp_browser_path = ""
state_json = ""
# END FACTORFORGE MODEL ACCESS
```

### 2.3 状态（`state_json`）

| 字段 | 内容 |
|---|---|
| `host_id` | `urn:uuid:` 形式的本机编号，ChatGPT 登录时交给供应商 |
| `oauth` | ChatGPT 账户的令牌（客户端编号、主体、ID/访问/刷新令牌、到期时间、最早刷新时间、授权范围） |
| `budgets` | 兼容通道两个通道的预算记录 |
| `omp` | 多供应商通道：`next_id`（下一个本地账户句柄）、`credentials`（凭据行）、`cache`（上游的键值缓存及到期时间）、`budgets`（按 `<供应商>:<句柄>` 的预算记录） |

一条预算记录是 {`start` 窗口起点, `last` 最近一次, `count` 次数, `ids` 请求编号}。每次载入都完整校验：句柄唯一且小于 `next_id`，供应商名合法，凭据是 `api_key`（非空密钥）或 `oauth`（访问令牌、刷新令牌、到期时间），预算记录的时间和计数自洽、编号不重复。不合格返回 `MODEL_STATE_INVALID`。

### 2.4 私有运行目录

- `runtime/model-access-omp`：模型目录缓存（每个账户一个数据库文件）和上游的工作目录（`agent`）。建立时权限 0700，必须属于当前用户，路径上没有符号链接。
- `runtime/model-cli-workspace/<程序>`：官方命令行程序的工作目录，同样不允许符号链接。

## 3 协议

两个 `serve` 都以“一行一个 JSON”工作：

- 按字节切行，不用逐行读取库，避免恶意的超长行无限累积；超过 `max_line_bytes` 返回 `REQUEST_TOO_LARGE` 并退出。
- 空行跳过。不是 JSON 的行返回 `{id: "invalid", ok: false, error: {code: "REQUEST_INVALID"}}`。
- 标准输出只写协议响应；输入在半行处结束时返回 `INCOMPLETE_REQUEST_LINE`。
- 失败响应是 `{code, delivery_unknown}`：`delivery_unknown` 为真表示请求可能已经到达供应商（可能已计费）。

公开契约在 `contracts/v2/model-access/`：`protocol.json`（v1）、`omp-protocol.json`（v2）、`response.schema.json`、`omp-generate-response.json`。

### 3.1 v2（`decodeOMP`）

| `op` | 必需字段 | 结果 |
|---|---|---|
| `status` | — | 开关、次数上限、预算窗口、各供应商的连接数、各账户的预算、暂停的账户、`account_validation: "ACCOUNT_VALIDATION_PENDING"` |
| `providers` | — | 全部登录入口：`id`、`name`、实际保存的供应商 `credential_provider`、`available`、`capability`（`text` 或 `tool_credential`）、已有连接数 |
| `accounts` | `provider` | 该供应商的本地账户句柄及凭据类型 |
| `models` | `provider` `account_id` | 目录来源 `source`、是否陈旧 `stale`、模型列表 |
| `generate` | `provider` `account_id` `model` `input` | 见第 5 章 |

- 请求只能含 `v`（必须为 2）、`id`、`op` 和该操作的必需字段。
- `id` 满足 `^[A-Za-z0-9_-]{1,128}$`；`provider` 满足 `^[a-z0-9][a-z0-9.-]{0,127}$`；`account_id` 是正整数；`model` 非空且不超过 256 字符；`input` 非空。
- 不接受凭据、任意网址或额外的 SDK 参数。

### 3.2 v1（`decode`）

`op` 为 `status`、`models`、`generate`，`channel` 为 `api` 或 `chatgpt`（`status` 可以不带通道）。`generate` 需要 `model` 和 `input`，其他操作不能带这两个字段。`PLAN_USAGE_LIMIT` 失败附带供应商的用量页面地址。

## 4 本地预算（`request-budget.ts`）

- **配置校验（`validateBudget`）**：次数上限为正而预算窗口不为正时返回 `BUDGET_WINDOW_REQUIRED`。
- **预占（`reserveBudget`）**：
  1. 当前时间早于记录的最近一次时，返回 `CLOCK_ROLLBACK`。
  2. 没有记录，或预算窗口为正且已过窗口时，开始新的窗口。
  3. 窗口内已有同一编号时返回 `DUPLICATE_REQUEST`。
  4. 次数上限为正且已达上限时返回 `LOCAL_BUDGET_EXHAUSTED`。
  5. 计数加一，记下编号和时间。次数不限时只保留最近 256 个编号（这只是去重记录的界限，不是次数上限）。
- **近期重复（`recentRequest`）**：编号在当前窗口（窗口为 0 时即全部保留的编号）中出现过。
- 预占在发送前持久保存，失败不退还。预算记录跨重启保留。
- 状态中的预算模式为 `unlimited`（次数上限为 0）或 `windowed`。

## 5 多供应商通道

### 5.1 凭据存储（`TomlCredentialStore`）

实现上游认证存储的公开接口，所有数据都在 `state_json` 的 `omp` 中，从不打开上游默认的 SQLite 凭据库。

- **新增与更新**：按上游的身份键（没有身份键时按凭据内容）匹配已有行；匹配到就更新凭据，否则分配新的本地句柄。
- **按内容条件更新**（`tryUpdateAuthCredentialIfMatches`、`tryDisableAuthCredentialIfMatches`）：只有当前凭据与调用者给出的旧值完全相同时才更新或删除。上游用它保证同一令牌只被刷新一次：两个刷新同时进行时，后到的那个发现旧值已变而放弃。
- **删除**：删除凭据行，并清空键值缓存；不保存供应商的错误文本或墓碑数据。
- 每次提交前完整校验状态，然后同步写入配置。登录时的存储另外绑定登录的取消信号：登录被取消后，任何提交都会失败，以免一个已取消的登录事后写入凭据。

### 5.2 供应商与账户（`OMPAccess`）

- **供应商列表（`providers`）**：来自上游的 OAuth 供应商注册表。有专门目录的三家（`openai-codex`、`google-antigravity`、`google-gemini-cli`）、有内置聊天模型或有模型描述的供应商，能力为 `text`，其余为 `tool_credential`。
- **供应商名（`provider`）**：接受登录入口名或它实际保存的供应商名，统一换成后者；不在注册表中时返回 `PROVIDER_INVALID`。
- **取得密钥（`key`）**：OAuth 凭据经上游按句柄取得访问令牌（必要时刷新）；刷新失败返回 `AUTH_REFRESH_FAILED`。API Key 凭据直接使用。

### 5.3 登录与退出

- **登录（`login`）**：为每次尝试单独建立一份绑定取消信号的存储（5.1），调用上游对应供应商的登录流程。网址、设备码、手动回填和隐藏输入都由菜单的对话组件显示。上游对允许免认证的本地供应商不返回凭据时，保存一条本地占位的 API Key 行；其他供应商没有凭据返回 `LOGIN_NO_CREDENTIAL`。取消返回 `LOGIN_CANCELLED`，其他失败返回 `LOGIN_FAILED`。失败时原有的连接不变。
- **浏览器会话（`captureBrowserSession`）**：只接受 `https` 网址；用 `omp_browser_path` 指定的浏览器和私有运行目录中的临时配置启动；Linux 上没有图形显示时返回 `BROWSER_DISPLAY_REQUIRED`；只取回登录要求的 Cookie，结束后只清理自己建立的资源。
- **退出（`logout`）**：账户必须存在。删除凭据行（上游若只做标记，也再删一次），删除该账户的目录缓存文件，返回 `{local_removed: true, remote_revocation_confirmed: false}`。

### 5.4 模型目录（`catalog`）

- 三家专门目录的供应商用各自的目录选项（需要访问令牌、账户编号或项目编号）；其他供应商用模型描述或上游内置的模型。
- 所有目录请求都带操作超时，不跟随重定向。
- 结果按 `<供应商>:<句柄>` 缓存在私有运行目录中，结果注明来源 `source` 和是否陈旧 `stale`。
- 只保留聊天模型。没有聊天模型且不是文本供应商时返回 `PROVIDER_NOT_TEXT`。

### 5.5 生成（`OMPService.handle` 与 `OMPAccess.generate`）

服务层依次：

1. 建立本次操作的截止信号：`timeout_seconds` 为 0 或超出计时器范围时返回 `LIMITS_REQUIRED`。然后检查开关、边界和预算配置（第 2.2 节、第 4 章）。
2. 该账户在本进程已因限流暂停时返回 `RATE_LIMITED`。
3. 近期重复的编号返回 `DUPLICATE_REQUEST`。这一步放在刷新令牌和读取目录之前。
4. 读取提示词，检查输入上限。
5. 读取目录，模型不在其中时返回 `MODEL_NOT_AVAILABLE`。
6. 确认未超时后，预占预算并同步保存。
7. 生成。成功结果是 `{provider, account_id, model, text, usage, prompt_hash}`，`prompt_hash` 为本次系统提示词的 SHA-256。整行响应超过 `max_line_bytes` 时返回 `OUTPUT_LIMIT_EXCEEDED`（送达未知）。
8. 限流失败时，暂停该账户（只在本进程内）。

适配层的生成：

- **请求**：系统提示词（如有）加一条用户消息，不提供工具。关闭有状态响应、服务端存储、上游的自动重试与循环保护；Codex 的流只尝试一次。上游要求等待重试时立即中止。
- **传输包装**：所有请求不跟随重定向，并受本次调用的中止信号控制。
  - 连接失败记为 `DELIVERY_UNKNOWN`（送达未知），并立即中止，防止上游重试一个可能已部分送达的请求。
  - 状态码映射：401 → `AUTH_REJECTED`，403 → `PERMISSION_DENIED`，429 → `RATE_LIMITED`，5xx → `PROVIDER_UNAVAILABLE`（送达未知），其他 → `REQUEST_REJECTED`。
  - 需要终态的 API，以及类型为 `text/event-stream` 的响应，每个字节块交给 `SSEGuard` 检查。Codex 的流在出现完成事件后立即结束读取。
- **流的检查（`SSEGuard`）**：只看帧结构和终态，内容仍由上游解析。
  - 累计字节超过 `max_line_bytes` 时返回 `PROVIDER_ENVELOPE_LIMIT`；非 UTF-8 或帧不是 JSON 时为送达未知。
  - 拒绝回答返回 `RESPONSE_REFUSED`：OpenAI 的拒绝事件和拒绝内容、Anthropic 的 `refusal`/`sensitive` 结束原因、Google 的安全类结束原因和提示被拦截。OpenAI 兼容接口的 `content_filter` 结束原因只记为终态，由上游解析后的结束原因决定成败。
  - 失败或不完整的响应返回 `INCOMPLETE_RESPONSE`。
  - 各家的完成事件或结束原因记为已到终态。对需要终态的 API（OpenAI 兼容、Responses、Codex、Anthropic、Google），流结束而没有终态时返回 `INCOMPLETE_RESPONSE`。
- **事件处理**：
  - 每个中间结果都检查输出：文本与思考文本合计超过 `max_output_bytes` 返回 `OUTPUT_LIMIT_EXCEEDED`；出现文本、思考和已脱敏思考以外的内容返回 `UNSUPPORTED_OUTPUT`。
  - 工具调用返回 `UNSUPPORTED_OUTPUT`。
  - 结束原因不是正常停止时返回 `INCOMPLETE_RESPONSE`。
  - 没有完成结果时为 `DELIVERY_UNKNOWN`。
- **结果**：拼接文本内容；空白文本返回 `EMPTY_RESPONSE`。用量只保留 `input`、`output`、`totalTokens` 中有限的非负数。
- 除取消外，所有未分类的异常都转成 `DELIVERY_UNKNOWN`；已经发出过请求或被取消时标为送达未知。

## 6 兼容通道

### 6.1 ChatGPT 账户（`OAuthAdapter`）

- **发现**：读取供应商的 OpenID 配置，签发者必须与登记值一致，各端点必须在签发者的域内。
- **登录（`login`）**：
  1. 在 `127.0.0.1` 的随机端口监听回调。
  2. 生成随机的 `state`、`nonce` 和 PKCE 校验码（S256）。首次登录用动态客户端注册，之后沿用已注册的客户端编号；带上本机编号 `host_id`。
  3. 把授权网址和回调端口交给终端显示；在 `login_timeout_seconds` 内等待回调，可取消。
  4. 校验回调，用授权码换取令牌，校验 ID 令牌后保存。已有登录时，新的登录必须是同一个客户端编号和同一个主体，不能换成另一个账户。
  5. 返回是否已登录、是否有直接使用计划的权限。
- **取得访问令牌（`access`）**：没有登录返回 `AUTH_REQUIRED`；没有直接使用计划的权限返回 `PLAN_PERMISSION_REQUIRED`。令牌未过期直接使用；过期后在允许的最早刷新时间之后刷新，并保存新令牌。刷新令牌失效（`invalid_grant`、`invalid_refresh_token`、`token_revoked`）时删除登录；其他拒绝返回 `AUTH_REJECTED`，保留登录。
- **退出（`logout`）**：删除本地令牌并请求远端撤销，返回撤销是否得到确认。
- **受限请求（`boundedFetch`）**：所有请求不跟随重定向，带超时，响应体超过上限时返回 `PROVIDER_RESPONSE_TOO_LARGE`（送达未知）。

### 6.2 目录与生成（`ModelService`、`ResponsesAdapter`）

- **连接**：`chatgpt` 通道用账户的访问令牌和供应商的 API 地址；`api` 通道用 `api_key` 和 `api_base_url`（没有 Key 返回 `API_KEY_REQUIRED`，地址为空或不合格返回 `API_BASE_URL_INVALID`）。
- **目录**：读取 `/models`。ChatGPT 通道只保留可列出的模型。
- **生成**：服务层依次检查开关与边界、通道暂停、近期重复、提示词与输入上限、模型在目录中，然后预占预算并生成。没有覆盖整个操作的截止信号：目录读取和生成各自按 `timeout_seconds` 计时。
  - 用 Responses API 流式生成，`store: false`，SDK 不重试，组织和项目强制为空，以免环境变量把请求挂到其他账户的计费项目上。
  - 输出文本增量超过 `max_output_bytes` 返回 `OUTPUT_LIMIT_EXCEEDED`。拒绝返回 `MODEL_REFUSED`，失败返回 `MODEL_FAILED`，不完整返回 `MODEL_INCOMPLETE`。没有完成事件为 `DELIVERY_UNKNOWN`；出现两次完成事件返回 `PROVIDER_PROTOCOL_INVALID`。
  - 完成后的输出只能是助手消息中的文本（跳过推理项），否则返回 `UNSUPPORTED_MODEL_OUTPUT`；空文本返回 `MODEL_OUTPUT_EMPTY`。
  - 结果是 `{channel, model, text, response_id, usage}`（不含提示词哈希）。
- **计划额度**：ChatGPT 通道收到计划额度用尽（`PLAN_USAGE_LIMIT`）时，本进程暂停该通道。普通的 429 只返回 `RATE_LIMITED`，不暂停。

### 6.3 官方命令行程序（`OfficialCLI`）

- **可执行文件**：路径必须是绝对路径，不能是脚本（`.sh`、`.bat`、`.cmd`、`.ps1`），路径上没有符号链接，文件头必须是本平台的原生可执行格式。未配置返回 `OFFICIAL_CLI_NOT_CONFIGURED`。
- **版本**：先运行 `--version`，只接受登记的版本，否则返回 `OFFICIAL_CLI_VERSION_UNSUPPORTED`。
- **环境**：只按白名单传递环境变量（主目录、路径、终端、语言、代理、证书、XDG 目录等），其他变量（包括模型和交易凭据）一律不传。
- **工作目录**：`runtime/model-cli-workspace/<程序>`。
- **状态**：Claude 用 `auth status --json` 读取登录状态；Antigravity 不提供机器可读状态，显示为“由官方终端确认”。输出受 `timeout_seconds` 和 `max_line_bytes` 限制。
- **交接**：要求终端，把终端交给官方程序完成登录或退出，P5 不读取它保存的凭据。

## 7 菜单

### 7.1 多供应商菜单（`runOMPMenu`）

用上游的终端组件构建：可搜索的选择列表、对话、提示输入（可隐藏）、确认和可滚动的长文本。

| 菜单项 | 逻辑 |
|---|---|
| 登录 / 添加连接 | 列出全部登录入口，调用 5.3 的登录；需要正数的 `login_timeout_seconds` 和 `timeout_seconds` |
| 选择账户与模型 | 选择本地句柄，读取目录，选择模型；不发送生成请求 |
| 显式模型调用测试 | 输入测试内容，确认后经 `OMPService` 以随机编号调用一次；结果只显示在终端 |
| 查看本地预算与连接状态 | 显示次数上限（0 显示“无限制”）、“供应商剩余额度：未知”和 `status` |
| 设置推理边界 | 逐项输入 `timeout_seconds`、`max_input_bytes`、`max_output_bytes`、`max_line_bytes`、`budget_window_seconds`、`omp_max_requests`；空输入保留原值；前四项必须为正，后两项可以为 0（`parseInferenceValue`）；整体通过 `validateInferenceLimits` 后，确认才保存并打开生成开关 |
| 退出一个连接 | 选择句柄，确认后调用 5.3 的退出 |
| 兼容通道菜单 | 见第 1.3 节 |

操作失败时，把错误码换成可以照做的中文说明显示（如缺少浏览器路径、缺少桌面环境、缺少边界）。

### 7.2 兼容菜单（`runMenu`）

在终端中提供状态查看、ChatGPT 登录与退出、官方程序交接、模型选择和本地预算设置，不提供测试调用。供应商给出的标签在显示前替换掉控制字符、双向文本控制符和行分隔符（`cleanText`），防止它们变成终端指令、伪造的行或看不见的选项。列表搜索使用按词局部匹配的模糊搜索。

### 7.3 运行环境隔离

- Bun 入口在加载上游代码之前（`omp-environment.ts`）删除白名单之外的全部环境变量，并把上游的工作目录指向私有运行目录，不使用用户自己的上游配置目录。
- 从 Node 启动 Bun 菜单（`launchOMP`）时使用相同的白名单。优先使用 `~/.bun/bin/bun`；找不到 Bun 时返回 `OMP_RUNTIME_REQUIRED`。
- Bun 入口、菜单和官方程序交接在收到 SIGINT 或 SIGTERM 时取消当前操作，关闭上游存储，释放配置锁。
- Node 兼容入口不清理自身的环境变量（它不加载上游代码），交给官方程序的环境另按白名单传递（6.3）。

## 8 上层的调用方式

应用实例经 `adapters/modelaccess.Client` 调用（P3 设计书）：

- 每次生成启动一个 `omp-cli.js serve` 进程，写入一行 v2 `generate` 请求，读取一行响应。超时后先发中断信号，再等清理时间。
- 进程启动失败返回 `MODEL_ACCESS_FAILED`；启动后进程失败或超时按送达未知处理（`DELIVERY_UNKNOWN`）。都不重试。
- 响应必须正好一行、合法 UTF-8、不超过行上限，编号、供应商、账户、模型与请求一致，`prompt_hash` 是 64 位十六进制，文本非空且不超过输出上限，用量只含三个已知键的非负数且不超过 2^53 − 1。成功与失败的字段不能同时出现。
