# 交易系统层设计书

版本：2.0；日期：2026年10月4日。唯一对应式样书：[交易系统层式样书](01_交易系统层式样书.md)。本文规定实现 S1 的代码，不引入策略业务要求。

## 1 代码生成范围与依赖

实现包 src/factorforge/trading，独立入口 trading-api、execution-sim、execution-live。本层安装包不得导入 strategy 或 applications；验收时在未安装上两层的环境启动。API 只调用本层 application 服务，确定性 domain 不依赖网络/数据库；adapters 实现本层端口。Python 3.11、FastAPI、PostgreSQL 沿用现有设计方向，确切依赖版本和锁文件在 P1 验证后冻结，不从旧设计猜供应商版本。

建议子包为 domain/{market,order,protection,account,risk}、application/{commands,queries,reconcile}、ports/{market,broker,clock,secret,store}、adapters/{sim,binance,postgres}、api、workers。BrokerPort 对所有交易对象提供相同能力；新增渠道只扩充适配器和能力探针。数据库、日志、配置和时钟是本层设施，没有上层回调才能工作的必选路径。

实例配置只通过通用接口传入。本层只认识 owner_id 和请求来源，不认识其策略类型。交易对象使用 InstrumentKey=(venue,product,instrument_id)，运行使用 RunKey=(environment,account_id,run_id)，environment 仅为 SIM/LIVE；历史回放和影子通过 SIM 的 execution_mode=REPLAY/SHADOW 区分，SHADOW不撮合。账号及所有外键带 environment，跨环境绑定拒绝。

## 2 数据类型和字段约定

此处类型是 v2.0 交易接口的设计真源，P1 据此生成 contracts/v2/trading 的机器契约、DTO 和校验；旧 contracts/openapi/v1.json 不参与生成。schema_version 固定为 trading-2.0，未知安全字段拒绝。金额、价格、数量为十进制字符串，内部 Decimal；不得用二进制浮点核账。情绪等数学量不属于本层。时间用带 Z 的 UTC ISO8601，同时保留交易渠道业务日；ID 为不透明字符串。

每个写请求公共字段：schema_version、request_id、idempotency_key、run_key、expected_version、reason、expires_at_utc；身份由已认证上下文取得，不能由正文中的 actor 或 environment 字符串授予权限。创建运行不要求 expected_version；其他命令以 aggregate_version 作乐观并发控制。响应公共字段：resource_id、aggregate_version、state、accepted_at_utc、correlation_id、reason_codes；accepted 表示本地命令持久化，不能表示成交。

| 类型 | 必需字段及语义 | 约束 |
| --- | --- | --- |
| InstrumentSpec | key, version, valid_from, price_tick, quantity_step, contract_multiplier, quote_currency, settlement_currency, min_notional, capabilities, price_roles | 乘数/步长正；交易能力枚举含LIMIT/MARKET/SHORT/CONDITIONAL_PROTECTION/REDUCE_ONLY等；不明用UNKNOWN |
| MarketPoint | instrument_key, source_id, kind, observed_at, received_at, available_at, value, currency, quality, spec_version | kind区分BID/ASK/LAST/MARK/INDEX/REFERENCE/FX；quality为VALID/STALE/MISSING/CONFLICT |
| Candle | instrument_key, interval, open_at, close_at, available_at, open/high/low/close, volume, source_id, final, revision | 正价格；high不小于低价及开收；final=false不进入完成K线集合 |
| AccountPolicy | version, valid_from, risk_day_zone, notional_limits, trade_loss_limit, margin_policy, daily_loss, drawdown, consecutive_loss, breach_action, recovery_policy | 三项账户亏损保护各含mode=OBSERVE/ENFORCE与阈值；缺关键值REQUIRED_UNSET |
| OrderRequest | owner_id, instrument_key, side, order_type, quantity, limit_price?, time_in_force?, reduce_only, position_side, spec_version, protection_plan? | 限价必需limit_price；新增实盘风险必需有效保护计划；未知模式拒绝 |
| ProtectionPlan | lot_id?, trigger_kind, trigger_price, covered_quantity, exit_order_type, max_slippage_policy, spec_version | 触发价格角色支持后才接受；覆盖量按实际成交追踪；减仓语义必须证明 |
| TargetRequest | owner_id, instrument_key, target_version, target_quantity, policy_version, spec_version, source_decision_id, protection_plan?, owner_epoch | 带符号数量；一对象一个活跃owner；所有潜在风险均计入 |
| OrderView | order_id, external_order_id?, client_order_id, owner_id, instrument_key, side, requested_quantity, filled_quantity, remaining_quantity, average_fill_price?, state, reduce_only, spec_version | 未成交无均价，不填0；状态见第5章 |
| Fill | venue, account_id, external_fill_id, external_order_id, instrument_key, side, quantity, price, fee, fee_currency, happened_at, received_at | 外部唯一键去重；账务只来源于实际或模拟成交事实 |
| PositionView | instrument_key, owner_id?, quantity, average_entry?, unrealized_pnl?, currency, reconciliation_state, protection_state, observed_at | 归属不明进入UNALLOCATED，不随意分配 |
| AccountView | equity?, available_margin?, currency, risk_day, realized_pnl, unrealized_pnl?, fees, funding, external_flows, risk_state, policy_version, observed_at | 净值不可靠时为null并携带质量；日损失不填0 |

可选字段仅在业务不适用时省略；未知必需安全数值禁止执行。查询列表响应 items 为上述具体类型，另有 cursor 和 snapshot_version，不使用通用 Record。API 错误为 Problem={code,message,field?,correlation_id,retryable,current_version?}；401未认证、403越权、404当前身份范围不存在、409版本/幂等冲突、422域/能力/单位错误、423风险锁/恢复核验、429限流、503设施失效。未知订单结果用业务状态UNKNOWN，不能用可重试503诱发新订单。

## 3 服务与接口

BrokerPort 实现 submit_order、query_order、cancel_order、list_open_orders、list_fills、get_positions、submit_protection、query_protection、cancel_protection、get_account、get_income、get_capabilities。MarketPort 实现 candles、latest_points、subscribe_updates、instrument_specs。端口接收结构化 DTO，返回受理/事实/未知结果，不暴露交易密钥。适配器负责供应商字段、签名、限速、错误码和普通/条件单不同协议。

| HTTP/命令 | 输入 | 输出及副作用 |
| --- | --- | --- |
| POST /api/v2/trading/runs | environment, account_binding, execution_mode, account_policy, initial_cash? | RunView；SIM本金必填；LIVE不创建资金 |
| GET /instruments, /market/candles, /market/points | InstrumentKey、区间、价格用途 | InstrumentSpec/Candle/MarketPoint列表；完整前缀同上 |
| POST /orders | OrderRequest及公共字段 | OrderView；经风险、预占、outbox执行 |
| GET /orders, /orders/{id}, /positions, /account | RunKey、查询游标 | OrderView/PositionView/AccountView；只在身份绑定范围查询 |
| POST /orders/{id}/cancel | 公共字段及order_id | 持久化撤单命令；订单仍未终态则继续计风险 |
| PUT /owners/{owner}/targets/{instrument} | TargetRequest及公共字段 | TargetView={target_version,target_quantity,actual_quantity,pending_quantity,delta_quantity,state,reasons} |
| POST /protections, GET /protections/{id} | ProtectionPlan/标识及公共字段 | ProtectionView={plan,external_id?,covered_quantity,state,verified_at?,reasons} |
| POST /protections/{id}/replace | 新计划、原版本及公共字段 | 替换状态；按第6章无空档顺序执行 |
| POST /protections/{id}/cancel | 公共字段、指定计划 | 仅已无对应敞口或有替代确认时允许 |
| POST /runs/{id}/reconcile, /stop, /resume | 模式、原因、版本及公共字段 | RunView；resume需核验结果和独立权限 |

RunView={run_key,execution_mode,state,policy_version,reconciled_at?,executor_epoch,active_owners,reasons}。Target状态为PENDING/RECONCILING/ACTIVE/BLOCKED/SUPERSEDED；ACTIVE不代表已经达成。CLI是本层API客户端，提供sim-create、market-read、order-submit/cancel、protection-set、account-show、reconcile；CLI不绕过服务。直接订单入口受owner占用冲突检查，不能在框架占用的归属上偷偷发单。

## 4 风险、目标差额与并发

RiskEngine输入不可变的AccountSnapshot、InstrumentSpec、AccountPolicy、未终态订单和请求。检查顺序：身份/环境 → 故障及恢复状态 → 数据和规则 → 交易能力/时段 → 归属 → 最不利敞口/保证金 → 单笔及组合压力 → 账户ENFORCE门 → 审计可用。输出 RiskDecision={approved,reasons,worst_exposure,reservations,policy_version,input_hash}。策略来源与人工来源不能改变顺序。

owner绑定表对(RunKey,InstrumentKey,position_side)作互斥所有权；初版同一账户同一产品不同时运行多个独立写者。不同交易对象/账户可以并行。将来需要同标的多策略共享时，以独立账户或经新增式样验证的分配器扩展，不靠净持仓猜归属。即使不同owner交易不同对象，其账户预算仍由单账户事务检查及预占。

对目标数量 q_target 先按数量步长向零取整。delta = q_target - q_actual - q_pending_valid；q_pending_valid只包含同一目标下仍有效的订单预期量。新目标先撤销旧增险单，确认后才能替换；未知旧单继续按最不利同时成交风险计入。反向目标先平旧方向且查询归零，然后新方向重新风险检查。人工改仓、ADL或强平使owner_epoch增加、目标BLOCKED；上层读取新事实并显式恢复目标epoch才能继续，旧epoch请求拒绝。

通用线性产品名义金额为 abs(q × price × multiplier)，损益为有符号q × multiplier × (exit-entry)，费用/资金费另记。非线性产品需另一个已验证AccountingPort，初版能力不支持就拒绝；不用线性公式硬套。每种价格用途来自InstrumentSpec，成交可行性用有效BID/ASK，保证金用批准MARK，策略价格代理由上层选择但本层返回真实质量。

OBSERVE 的账户日损失/回撤/连亏只输出would_trigger记录，不向可用预算、目标缩减或锁状态注入间接约束。其他硬限照常。Π_day=equity_marked-equity_start-net_external_inflow，L_day=max(0,-Π_day)；金额或比例任一ENFORCE阈值达到则锁定。原风险日基准、外部资金流和锁持久化；浮盈恢复、转账及重启不自动解除。新风险日如何解除按recovery_policy，必须完成对账。

风险配置必须有有效版本、依据和启用范围。ENFORCE缺breach_action或风险默认值证据未满足实例准入时拒绝LIVE启动。breach_action枚举KEEP_PROTECTION/ORDERLY_REDUCE/EXIT_WHEN_TRADABLE；不替用户选择。连续亏损接受经成交和净成本核验的完整仓位周期关闭事实，不接受上层任意写一个亏损次数；没有框架时本层PositionCycle也可形成该事实。

## 5 订单状态、幂等与账务事务

订单主状态：CREATED → RESERVED → DISPATCHING → ACKNOWLEDGED → PARTIALLY_FILLED → FILLED；旁路为REJECTED、CANCEL_PENDING、CANCELED、UNKNOWN。撤单和成交并发时，以累计成交事实确定filled/remaining，不能由较晚到的撤单响应覆盖成交。终态更正仅追加外部事实，不复用旧请求ID。

幂等表唯一键为(environment,account_id,principal_id,idempotency_key)，保存规范请求哈希和已产生的resource_id。相同键相同正文返回原结果；不同正文409。client_order_id从本地order_id稳定生成，不因网络重试更换；实际供应商长度/字符限制由适配器测试冻结。

同一数据库事务锁account及owner，校验expected_version，写order/target、risk_decision、资金/敞口reservation、audit和outbox；失败则无可投递订单。网络调用在事务外，没有数据库与交易所原子事务。outbox至少一次投递，执行前再检查期限、risk_policy、executor_epoch和最新风险；收到未知响应先查询稳定客户端ID，无法确认则UNKNOWN并锁增险。UNKNOWN预占不释放，只有确定未受理/撤销才释放剩余额度。

存储表：trading_run、account_policy_version、instrument_spec、market_snapshot_ref、owner_binding、target_request、order、protection_order、fill、income_entry、position_lot、position_cycle、risk_day、risk_lock、risk_reservation、reconciliation_report、command_dedup、audit_event、outbox。所有运行事实带RunKey，fill和income按渠道外部业务ID唯一；本层数据库角色独占其表，上层无直写权限。

SIM和LIVE用独立schema、数据库角色、执行进程和凭据目录；跨schema外键/查询禁止。账户净值是成交/收入账本投影，查询交易所结果形成核验事实；差异不能被投影静默覆盖。真实原文、模型会话不是本层表的内容。

## 6 保护、执行权与异常恢复

每次新增实际成交建立risk_lot并执行ProtectActualFill；未确认保护时 lot为UNPROTECTED，暂停增险并按预定政策保留/退出，持续告警。部分成交只保护已成交量，不以订单原总量假装全部有保护。保护状态为PENDING/ACTIVE_VERIFIED/TRIGGERED/EXIT_PARTIAL/CLOSED/UNKNOWN/FAILED。

保护替换先创建并查询新保护，确认覆盖后撤旧；若供应商不允许重叠，必须通过能力验证可原子修改，否则禁止该替换路径或先安全降险。任何时候保护覆盖状态与实际仓位对账。触发只表示条件成立，继续追踪成交、残仓及费用。存量保护不放宽；减仓型保护不能因为side或仓位模式不符变成反向开仓。

execution-live唯一持有签名凭据。每账户只有一个经确认的执行主，使用executor_epoch及数据库租约；租约丢失停止出站。数据库租约不能证明旧进程已经无法发单，切主还需确认旧进程/凭据出口已隔离；无法确认时不启动新主。双主故障注入验证不能只测一行租约SQL。

运行状态INITIALIZING/NORMAL/DEGRADED/RISK_LOCKED/EMERGENCY/RECOVERY_CHECK/STOPPED。启动先查询普通单、条件单、成交、收入、仓位、保证金和规则，与本地订单ID及风险锁核对；对所有UNKNOWN查清或保持BLOCKED。恢复完成需要账差归零或签署差异解释、外部变更归属明确及保护可确认；独立resume命令才可回NORMAL。保护和强制减险工作池优先于普通发单及行情批量下载。

API/数据库失效时不得靠本地旧缓存继续增险。残仓的最后处置为已准备的官方交易渠道人工runbook：确认账户 → 隔离旧自动执行 → 查实际仓位/普通及条件单 → 撤增险且保留必要保护 → 按预签触限政策减险 → 留存外部ID及前后事实 → 恢复后导入并对账。若独立复核职责无法落实，实盘准入保持未通过；不假定已有第二名操作人员。无有效预案时不提供未经验证的离线签名发单脚本。

## 7 仿真与供应商适配

SimBroker实现完整BrokerPort，使用固定种子及冻结成交规则；输入时钟来自ReplayClock，不读系统当前时间决定历史成交。市价按下一可用可成交报价加费用/滑点，限价须考虑排队/成交量；无逐笔时保存OHLC路径歧义，选择登记的保守规则或区间。模拟保证金、资金费、强平、部分成交、撤单不确定及停盘；资金不足不能自动注资。SHADOW只保存目标和意图。

BinanceAdapter按能力探针映射普通/条件单，查询与撤销分别使用供应商适用接口。动态读取交易规则并保存版本；目标产品/账户/协议接受状态仍需实际核验。官方文档已于2026年10月4日核对普通交易及条件订单的入口分类，具体参数在适配器契约探针中冻结，不把公共文档当目标账户已授权证据。[Binance交易接口](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/trade)

不同venue适配器跑同一BrokerPort契约测试，合约特有收入与公司行动输出通用TypedIncome/InstrumentChange，由核账及恢复流程处理，不能在策略包写供应商私有API。
