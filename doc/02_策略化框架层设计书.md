# 策略化框架层设计书

版本：2.21.0

对应式样书：[02_策略化框架层式样书](02_策略化框架层式样书.md)。源码在 `src/factorforge/strategy`，测试在 `tests/strategy`。文中出现的数值都是示意值，实际取值由各实例的私有登记决定。

## 1 结构

### 1.1 包

| 包 | 职责 |
|---|---|
| `domain` | 状态、记录类型与纯计算：账本、合成、档位、止损、风险单位、案例、学习、分层账本、预排事件 |
| `application` | 命令（对象、事件、评分、因子观测、止损指令、退出请求、转基线、时段）、决策周期、下发、查询 |
| `adapters` | 交易层客户端 `TradingV2`、内存实现与重放时钟 |
| `adapters/postgres` | 存储与归档 |
| `adapters/configuration` | 读取私有配置 |
| `api` | HTTP 接口与契约 |
| `workers` | 调度与回报循环 |
| `entrypoints/*` | 进程入口 |

### 1.2 进程与身份

| 进程 | 身份 | 作用 |
|---|---|---|
| `strategy-api`（公开） | 公开身份 `PublicPrincipal` | 研究评分、查询；只能写公开部分的状态 |
| `strategy-api`（内部） | 工作负载身份 `WorkloadIdentity` | 上层应用写入可交易的评分、观测、指令 |
| `strategy-scheduler` | 工作负载身份 | 每轮执行决策周期，再下发目标 |
| `strategy-feedback` | 工作负载身份 | 每轮读取交易层回报、更新案例，再下发目标 |
| `factorforge-strategy` | 二者之一 | 命令行工具：初始化、单次命令；以工作负载身份执行的单次命令（`--internal`）只允许在 SIM，LIVE 返回 `MANUAL_WORKLOAD_CLI_SIM_ONLY` |

- **公开身份**：带权限范围（`query`、`score:research`、`object:write`），提交的评分只会成为研究评分（`RESEARCH_ONLY`），不能进入交易。
- **工作负载身份**：带信号能力 `signal:sim` 或 `signal:live`，以及可操作的对象列表，由初始化时写入的授权表核验（`CheckWorkload`）。

所有命令都检查身份所属的实例和环境（`Authorize`）。

## 2 状态与存储

### 2.1 状态

每个实例的全部状态是一个 `StrategyState`，包括：

- 对象、策略、参数快照。
- 事件及其各版本、评分、准入回执、提前计价评估。
- 贡献与账本。
- 价格样本、决策、目标发件箱、风险窗口占额、亏损案例、案例。
- 归因、学习候选与决策、反事实、因子清单。
- 因子序列、预排日程与模板、分层账本。
- 止损指令及其写入方、退出请求、转基线记录、风险批次。
- 审计与去重记录。

### 2.2 存储（`adapters/postgres`）

- **状态分两份保存**：
  - 公开部分（`public_state`）：版本、对象、事件、评分、研究回执、研究止损指令、去重、归因等，字段由 `publicFields` 列出。
  - 内部部分（`internal_state`）：其余所有字段。
  - 公开进程只能修改公开部分；改动内部部分或账本时返回 `PUBLIC_INTERNAL_STATE_FORBIDDEN`。
- **账本单独存表**：账本行逐条追加到 `sentiment_entry`，进程内缓存已读的前缀，每次只读新增的行。
- **审计**：审计追加到 `audit_event`，不可修改。
- **归档**：
  - 完整决策保留 6 小时（`DecisionRetention`）。超过 6 小时且不再被引用的决策移入 `decision_archive`；最新决策、最近已确认的决策、未结案例引用的决策、未结算目标和有效占额引用的决策不归档。状态里只留执行所需的精简信息（`TargetDecision`、`CompactDecisionInput`）。
  - 被精简掉的因子观测移入 `factor_observation_archive`。
  - 过期的止损指令移入 `stop_directive_archive`（研究指令移入 `stop_directive_research_archive`）。
  - 查询和幂等重放会到归档表里找。
- **价格样本**：每个对象最多保留 5000 条（`MaxSamplesPerObject`），并按策略需要的时间窗修剪（`RetainSamples`）。
- **体积告警**：内部状态超过 2 MiB 时输出 `STATE_SIZE_HIGH`。

### 2.3 命令管线（`Service.Command`）

与交易层相同，按以下顺序执行：

1. 锁定状态。
2. 身份核验（`Authorize`，在锁内执行）。
3. 去重：内容相同返回原结果，不同返回 `IDEMPOTENCY_CONFLICT`。
4. 版本检查：版本不符时返回 `AGGREGATE_VERSION_CONFLICT`。
5. 执行业务。
6. 版本 +1，写审计。

后台循环的一次处理（tick）遇到下列快照冲突时，重新读取状态和交易层快照，最多试 3 次，每次间隔 200～800 毫秒随机（`RetryTick`）：

- `CYCLE_SNAPSHOT_CONFLICT`
- `FEEDBACK_SNAPSHOT_CONFLICT`
- `TRADING_SNAPSHOT_CONFLICT`

重试成功时输出 `RETRIED <原因> <次数>`；3 次都失败时，这一轮放弃，下一轮重做。

## 3 登记：对象、策略与参数

### 3.1 初始化

`factorforge-strategy` 的初始化命令（`Initialize`）从私有配置的 `initial_registry` 读取以下内容，建立实例并授予工作负载权限：

- 策略：`policies`。
- 参数快照：`parameters`。
- 因子清单：`factor_manifests`。
- 因子序列：`factor_series`。
- 预排模板：`templates`。
- 止损指令写入方：`stop_directive_writers`。

对象之后用 `POST /objects` 创建，并引用策略版本与参数版本（`CreateObject`）。

### 3.2 对象

观测对象 `ObservedObject` 记录以下内容：

- **绑定**：实例、环境、交易运行（`trading_run_key`）、交易对象、归属者 `owner_id`、状态（`ACTIVE` 等）。
- **引用的版本**：策略版本 `time_policy_version`、参数版本 `parameter_version`、价格代理与状态的清单绑定。
- **运行中的状态**：
  - 档位、方向。
  - 上次周期与截止时刻、实际与在途数量、恢复状态。
  - 核心方向与反向候选（第 5.4 节）。
  - 风险单位、再入场门、判断链（第 6 章）。
  - 已执行的事件前降险。

同一交易运行中，与其他对象共用归属者或交易对象时，登记返回 `OBJECT_OWNER_CONFLICT`。

对象暂停或归档时仍处理现有持仓。有未结案例，或实际或在途数量不为零时，不能归档（`OBJECT_HAS_UNSETTLED_CASES`）。

### 3.3 参数快照

参数快照 `ParameterSnapshot` 是不可变的版本记录：

- **身份**：`version`、`parent_version`、`scope`、`valid_from`。
- **取值 `values`**：

| 键 | 含义 |
|---|---|
| `w` | 来源可信度权重，负值表示反向来源 |
| `g` | 状态乘数 |
| `h` | 默认半衰期（秒） |
| `eta` | 价格兑现的权重系数；`eta_anchor` 为 1 时 `eta` 不参与学习 |
| `kappa` | 价格兑现预算的倍数 |
| `k_stop` | 噪声止损的倍数 |
| `factor:<因子>`、`layer:<分量>` | 学习得到的因子权重和分量权重 |

- **学习约束**：`bounds` 是每个可学习参数的上下界，`steps` 是固定步长。`evidence_gates` 是学习门槛（第 8.3 节），各项均为数值：最少样本组、有效样本量、重复次数、置信度、死区、尺度、遗忘时长、冷却、漂移预算、置信区间、最小改进、反向门槛、晋升天数。
- **来源与范围**：`source_manifest` 是登记来源，`applicability` 是适用范围。
- **质量 `quality_state`**：模拟只接受 `EXPERIMENT_ONLY` 或 `VALIDATED`（`RiskQuality`），实盘只接受 `VALIDATED`。不满足时，评分只能成为研究评分，决策也不增险。

`w`、`g`、`h`、`eta`、`kappa`、`k_stop` 中任何一个未设置时，对象只做衰减和记录，决策理由为 `PARAMETERS_REQUIRED_UNSET`，不产生交易。

### 3.4 策略

策略 `Policy` 也是不可变的版本记录。下面先列出总体字段，其余字段在使用它们的逻辑处说明：

- `version`、`quality_state`（同参数快照的规则）、`source_manifest`。
- `cycle_seconds` 是决策周期；周期按 `window_anchor` 对齐，周期编号 = ⌊（时刻 − 锚点）/ 周期⌋。
- `max_price_age_seconds`：价格样本超过这个时长就标为过期。
- `target_ttl_seconds`：下发的目标从决策时刻起的有效期。
- `numerical_tolerance`：账本守恒和二分搜索的容差。
- `epsilon`：防止除零的下限。
- `composition` 为空时，走不带合成的旧路径（第 5.6 节）；不为空时，走分量合成（第 5 章）。

## 4 事件、评分与情绪账本

### 4.1 事件（`RegisterEvent`）

事件 `Event` 的内容：

- 身份与关系：事件族 `family_id`、事实版本 `fact_version`、父事件与关系（`NEW`、`CORRECTION`、`RETRACTION` 等）。
- 内容：主体、类型、发生与首次公开时间、证据、事实声明 `claims`、关联对象。

受理时的校验：

- 每条事实声明的验证清单在策略的 `rubrics` 内，权重等于策略 `claim_weights` 中该经济项目的登记值。
- 每条证据的验证引用在 `verification_manifests` 内。
- 事实版本：新事件必须从 1 开始；已有事件的修订必须是上一版本 + 1，且关系不能是 `NEW`。
- 不同事件族之间，主体、经济项目、期间和规范化事实都相同的声明返回 `FACT_FAMILY_CONFLICT`（同一事实不能用两个事件族重复进入账本）。

`VerifyEvent` 的判定：

- 以下任一情况，事件为 `QUARANTINED`：事件证据为空；事实声明为空；声明跨越多个主体、经济项目或期间；同一族内的事实身份不一致；验证时刻晚于当前；引用的证据在验证时尚不可用。
- 否则为 `VERIFIED`；关系为 `RETRACTION` 时为 `RETRACTED`。
- **新颖度** = 本事件里未在同族旧版本出现过的事实权重 ÷ 全部事实权重。已有事件的 `CONFIRMATION` 和 `CORRECTION` 修订沿用上一版本的新颖度；事实键发生变化的 `CONFIRMATION` 被隔离。

### 4.2 评分准入（`Submit`）

评分 `ScoreSubmission` 带：

- 方向与影响点数。
- 可信度、相关度、新颖度、预期覆盖、提前计价比例、预计半衰期、质量。
- 证据、评分者、评分量表版本、标定版本、输入清单哈希。

内容与已有评分完全相同的提交，直接返回已有回执。同一事件和对象已有工作负载身份提交、且状态不是 `DRAFT`、`RESEARCH_ONLY`、`QUARANTINED` 的评分时，新评分必须声明为修订（`EXPLICIT_REVISION_REQUIRED`）。修订引用的评分属于这一组时，必须是最新的那一个且版本号连续，否则返回 `SCORE_REVISION_CONFLICT`。

准入回执的状态按以下顺序判定，命中第一条即停：

| 条件 | 状态 | 理由 |
|---|---|---|
| 有缺失或未知的向量字段 | `DRAFT` | `UNKNOWN:<字段>` |
| 公开身份提交 | `RESEARCH_ONLY` | `PUBLIC_RESEARCH_IDENTITY` |
| 事件未验证、评分证据为空或证据不在事件内 | `QUARANTINED` | `INVALID_EVIDENCE` |
| 标定版本不在 `calibrations` 或量表不在 `rubrics` | `QUARANTINED` | `UNCALIBRATED_SCORE` |
| 实盘使用 `experiment_calibrations` 中的标定 | `QUARANTINED` | `EXPERIMENT_CALIBRATION_LIVE` |
| 预计半衰期超出 `half_life_bounds` | `QUARANTINED` | `HALF_LIFE_NOT_VALIDATED` |
| 策略或参数的质量不合格 | `RESEARCH_ONLY` | `PARAMETERS_UNVALIDATED` |
| 事件类型在 `prepricing_modes` 中登记为 `NOT_ASSESSED` | `READY_PENDING_PRICE`，提前计价比例记为 0 | `PREPRICING_NOT_ASSESSED` |
| 其他 | 按第 4.3 节评估提前计价，通过为 `READY_PENDING_PRICE`，否则 `QUARANTINED` | — |

**可用时刻** = max（当前、评分完成、证据可用、事实验证）。到这个时刻之后，下一个决策周期才处理该评分。

判断型事件类型列在 `judgment_event_types` 中，配合 `prepricing_modes` 与 `experiment_calibrations` 使用（式样 S2-039）。

### 4.3 提前计价评估（`AssessPrepricing`）

非判断型评分需要一份登记的提前计价清单。清单键为 `prepricing:<输入清单哈希>`，要求以下各项齐全且一致：

- 输入清单哈希、标定版本、验证清单（必须在 `verification_manifests` 内）、授权引用；清单已验证（`validated` 为真），且其可用时刻不晚于当前。
- 时间顺序：训练截止 ≤ 事前价格时刻 ≤ 价格可用时刻 ≤ 评分完成。
- `beta`：等于策略的 `beta`，即相对基准的系数。
- 预期覆盖：等于评分值。

判定：

- **预期已覆盖**（`coverage_mode` 为 `EXPECTATION_COVERED`，且价格证据都是预期证据）：提前计价比例为 0。预期覆盖为正时必须有预期证据。
- **未被覆盖**（`UNCOVERED_PRICE`）：价格证据不能为空，且不能与预期证据重叠；比例 = min（1，max（0，方向 ×（ln（现价/事前价）− `beta` × 基准收益））/ rho）。
- **没有基准收益**：只有 `absolute_price_proxy_validated` 为真时，才按绝对价格计算。

### 4.4 注入（`InjectReady`）

对已到可用时刻、准入为 `READY` 或 `READY_PENDING_PRICE` 的评分，有有效价格样本时处理。注入前再确认事件当前仍为 `VERIFIED`、且有保存的提前计价评估，否则回执改为隔离。价格样本没有基准值、且未登记绝对价格代理时，暂不注入（`PRICE_PROXY_UNVALIDATED`）。

**影响量（`ScoreAmount`）**：

- 半衰期：取参数 `h`；`event_half_life_approved` 为真时，改用评分的预计半衰期。选用的半衰期（包括 `h`）都必须在 `half_life_bounds` 内。
- 未预期部分 u =（1 − 预期覆盖）×（1 − 提前计价比例）。
- 影响量 = |影响点数 × 可信度 × 相关度 × 新颖度 × u × `w` × `g`|，再与 `event_cap` 取小。新颖度取事件核验得到的值，不用评分里提交的新颖度。

**接受量** = min（影响量，`family_cap` − 同族剩余，`object_cap` − 对象正负剩余之和）。方向为中性时接受量为 0。

**方向**：评分方向；`w` 为负时取反。

**建立贡献**：

- 贡献 `Contribution` 记下参考价格和基准、冻结的参数版本、半衰期、兑现系数、质量和事实权重。
- 事件类型在 `realization_disabled_types` 中时，该贡献不参与价格兑现。
- 先记一条 `INJECTION` 账本行，再按可用时刻到当前的时间衰减记一条 `TIME`。参考价格缺失或早于一个周期时，改用当前样本作参考，生效时刻随之后移。

**修订**：修订评分在同一对象、同一事件的原贡献上记 `SCORE_REVISION` 差额；原贡献已失效时拒绝。新的剩余量是原贡献从生效时刻起，按账本历史重算衰减、兑现和失效之后的值，并重新受三级上限约束。修订不能改变方向。

### 4.5 账本推进（`AdvanceContributions`）

每个决策周期，对每个有效贡献：

1. **时间衰减**：剩余 × 2^(−经过秒数 / 半衰期)，记 `TIME` 行。
2. **清除条件**：满足任一即记 `EXPIRED` 行，剩余清零：
   - 年龄达到 `event_ttl_seconds`。
   - 剩余不高于 `cleanup_threshold`。
   - 剩余不高于 `cleanup_fraction_of_initial` × 初始量。
3. **价格兑现**：
   - 方向收益：有基准时用超额收益 ln（现价/参考价）− `beta` × ln（基准/参考基准）；否则在 `absolute_price_proxy_validated` 时用绝对收益；两者都不满足则跳过兑现。
   - 收益乘以贡献的方向后，只有创新高（高水位上移）的部分才计入。
   - 同方向的贡献共享一份预算：`kappa` × 本周期最大高水位增量，按（剩余 × `eta` × 增量）加权，用注水法（`Waterfill`，每份不超过自身剩余）分配，记 `PRICE` 行。
4. **校验**：推进后校验账本：每行的收支等式成立，开始值与上一行的结束值相差不超过 `numerical_tolerance`，结束值不为负，各贡献的剩余与账本结束值一致。不满足时返回 `MODEL_LEDGER_BROKEN`，整个周期的事务中止，不提交任何结果。

**撤回与更正**：撤回事件的贡献整体失效（`RETRACTED`）；更正事件中被移除的事实，按权重比例记 `CLAIM_INVALIDATED`。

**池视图（`Pool`）**：正向合计、负向合计、净值，以及按剩余量加权的平均质量。

## 5 应持仓位

### 5.1 输入

每个周期从交易层读取快照（`TradingV2.Snapshot`）：

- 权益、风险锁、运行状态、实际与在途数量、归属世代、目标版本。
- 品种规则、标记价、已完成 K 线（周期由 `candle_interval` 决定，回看 `history_seconds`）。
- 成交（含是否为保护退出、角色）、保护、均价、资金费观测。

价格样本取标记价。有登记的价格代理清单时，样本另带波动、流动性和基准。

模拟环境里，走合成路径、且没有有效的已验证价格代理清单的对象：

- 还没有任何价格样本时，用最近一根已完成 K 线的收盘价补价格（已有的过期样本不会被替换）。
- 流动性按 `liquidity_budget` 假设，决策理由带 `LIQUIDITY_ASSUMED`。

### 5.2 基线与研判

- **因子序列**：每个因子由定义 `FactorDefinition` 说明，包括 `factor_id`、用途 `purpose`（`BASELINE` 或 `ASSESSMENT`）、取值范围 `value_min` 与 `value_max`、上报周期 `cadence_seconds`、来源 `source_manifest`。
- **观测提交**：`POST /factor-observations`，内容包括可用时刻、取值、是否强制减险、输入哈希、证据、替代的旧观测、是否再确认、理由代码。可用时刻不能晚于当前，也不能早于该因子上一条观测。只有最新、且未被决策引用的观测可以被替代。每个因子最多保留 512 条观测（`MaxFactorObservations`）。

合成规则 `Composition` 中与输入有关的字段：

- **`baseline`**：基线因子列表 `BaselineFactor`。
  - `factor_id`、`weight`：各权重绝对值之和不超过 1。
  - `state`：`ENABLED`、`SHADOW` 或 `DISABLED`。
  - `max_age_seconds`：观测有效期。
  - `evidence_ref`：启用时必填的证据引用。
  - 基线值 = clip（Σ 权重 × 观测值 × 分量乘数 `layer:BASELINE`，±1）。
  - `allow_short_baseline` 为假时，基线不低于 0。
- **`assessment`**：研判因子 `AssessmentFactor`，有 `factor_id`、`state`、`max_age_seconds`、`evidence_ref` 和 `force_reduce`（没有 `weight`）。研判值 = 观测值 × 分量乘数 `layer:ASSESSMENT`。研判为 `ENABLED` 且有未过期的观测时，`force_reduce` 为真或观测本身带强制减险，本周期只减不增；没有新的观测时，这个标记不起作用。
- **缺失的处理 `missing_policy`**（只用于基线因子；研判缺失或过期时立即按 0）：
  - `ZERO`：缺失按 0。
  - `HOLD_REDUCE_ONLY`：已启用的基线因子在第二个有效期内沿用上一观测，但只减不增（理由 `BASELINE_STALE`），之后才按 0。

学习得到的因子权重和分量状态，来自参数快照里的 `factor:` 和 `layer:` 键（`EffectiveComposition`）。策略记录本身永不修改，回滚时一并恢复。

### 5.3 预排事件

日程 `ScheduledEvent` 由 `POST /scheduled-events` 登记：类型、预计时刻、确定程度（`CONFIRMED` 或 `ESTIMATED`）、来源、修订号、状态。可以带应用算好的窗口时刻。

模板 `ScheduledTemplate` 按“事件类型/窗口”登记：

- 窗口：`start_offset_seconds` 与 `end_offset_seconds`，相对预计时刻。
- 确定程度：`certainty_required`，要求日程达到的确定程度。
- 先验：`prior` 是 `TemplatePrior`，包括 `mean`、`n0` 和 `evidence_ref`；`n0` 大于 0 时必须有证据。
- 映射：`scale` 与 `cap`。窗口内的调整量 = clip（估计均值 / 尺度，±1）× 上限。
- 估计均值 =（`n0` × 先验均值 + 有效样本数 × 统计均值）/（`n0` + 有效样本数）（`Estimate`）。
- 统计门控：`min_n` 与 `gate_t`。`n0` 大于 0 时直接通过；否则要求有效样本数大于 1 且不少于 `min_n`，t 值不低于 `gate_t`。
- `forget_cases`：遗忘的案例尺度。
- `stats`：运行中的统计。
- `state`：`ENABLED`、`SHADOW` 或 `DISABLED`。

窗口的生命周期（`AdvanceScheduled`）：

- 窗口在开始时由 `PENDING` 变为 `OPEN`，并记下起始价格；结束时变为 `CLOSED`，形成一个窗口案例。
- 窗口案例只记录收益，不更新模板的统计（式样 S2-042）；已有的统计仍参与估计。
- 日程修订先按旧版本推进，再修改，所以已经开始的窗口不受影响；取消使 `PENDING` 和 `OPEN` 的窗口都作废（`VOID`）。

预排分量为所有开启窗口的调整量之和，再按合成规则里的 `scheduled`（`LayerCap`，含 `state` 与 `cap`）裁剪。

### 5.4 合成（`Compose`）

1. **核心** = clip（基线 + 研判 + 预排，±1）。
2. **调整分量**：
   - 置信度 = 质量 × |净值| /（正 + 负 + ε）。
   - 调整 = clip（净值 / `scale`，±1）× `cap` × 置信度。`scale` 和 `cap` 来自合成规则里的 `adjustment`（`AdjustmentRule`）。
3. **合成值（`Combined`）**：
   - 核心为 0 时，取 clip（调整，±`event_only_cap`）。
   - 核心加调整后方向改变时，取 0（压到空仓）。
   - 否则 clip（核心 + 调整，±1）。
4. **档位（`LevelFor`）**：合成规则的 `levels` 是一组 `Level`，每档有 `exposure`、`enter`、`exit`，退出阈值必须低于进入阈值，各档严格递增。
   - 从上次档位开始反复检查：强度低于当前档的退出阈值就降一档，达到下一档的进入阈值就升一档，直到不再变化，所以一次可以跨越多档。
   - 这个等值滞回的实现改编自开源项目 Financier（MIT），见 `THIRD_PARTY_NOTICES.md`。
5. **反向确认**：
   - 对象还没有记住核心方向时，以实际持仓的方向为准；空仓时取新的核心方向。
   - 核心方向不为零、且与记住的方向不同时，记下反向候选。核心方向为零不触发反向确认。
   - 在 `reverse_confirm_seconds` 之内保持原档位和原暴露（理由 `REVERSE_CONFIRMING`）。
   - 时间到后，改认新方向。
   - 这个确认期取合成规则 `rebalance` 里的值（`RebalanceRule`）。
6. **暴露（`CompositionExposure`）**：方向 × 档位的 `exposure` × 流动性系数。流动性系数 = min（1，min（流动性，`liquidity_budget`）/ max（权益 × 档位暴露，ε））。合成路径不使用波动或状态乘数。
7. **强制减险时**：暴露不得超过当前暴露，方向不同时取 0（理由 `FORCE_REDUCE_ONLY`）。
8. **只记录分量**：`SHADOW` 状态的因子或分量也计算一遍假设的核心、合成、档位和暴露，存入决策的 `shadow` 字段，不影响目标。
9. **触发分量**：与上次执行的决策相比，变化最大的分量记为触发分量，用于分摊调仓成本（第 8.4 节）。

### 5.5 从暴露到数量

- **普通模式**：数量 =（暴露 × 权益）/（价格 × 合约乘数），按数量步长向零取整（`Quantity`）。
- **风险单位模式**：按第 6.1 节计算。

结算币种与账户币种不同时，暴露取 0（理由 `FX_OR_CURRENCY_UNKNOWN`）。品种不能做空时，负目标改为 0（理由 `SHORT_UNAVAILABLE`）。

### 5.6 不带合成的路径

`composition` 为空的策略：

- 档位由池净值决定，档位来自策略本身的 `levels`。
- 暴露 = 方向 × 档位暴露 × min（1，`sigma_ref` / max（波动，ε））× 流动性系数 × 置信度（`Exposure`）。
- 反向按策略的 `reverse_confirm_seconds` 确认，未登记时只保持原意图（`REVERSE_CONFIRM_POLICY_REQUIRED`）。
- 市场状态按登记的状态清单计算（`UpdateRegime`）：维度为趋势、波动、风险偏好、行业、极端。指标达到 `regime_enter` 时进入高或低状态，回到 `regime_exit` 以内（不含等于）时退出。切换需要 `regime_confirmations` 次确认，并停留 `regime_dwell_seconds`；从 `UNKNOWN` 切出时只需确认次数，不需要停留。趋势维度用 `trend_window_seconds` 作回看窗口。
- 任一维度为未知时，暴露乘以 `unknown_regime_multiplier`。

这条路径只为兼容已有策略保留，不从价格判断方向的新策略都应声明 `composition`。

## 6 风险批次与止损

### 6.1 风险单位（`DynamicTarget`、`freezeUnit`）

合成规则声明了 `sizing`（`SizingRule`，`mode` 为 `RISK_UNIT`）时，依次检查：

1. **收盘止损退出**：有已受理的退出请求时，目标为 0，强制执行（第 6.4 节）。
2. **方向变化**：合成方向不为零、且与判断链或再入场门的方向不同时，清除它们；合成方向为零时保留。
3. **档位比例**：档位比例 = 当前档位的 `exposure`。
   - 方向与已冻结批次相同：目标 = 方向 × Q × 档位比例，按步长取整。
   - 已有同向持仓但没有冻结批次：保持当前数量，不放大（`RISK_UNIT_UNTRACKED_POSITION`）。
   - 否则提出一个新批次，交给后面的门控决定。
4. **判断链**：合成规则 `chain_loss`（`ChainLossRule`）中，同向链的累计亏损达到 `max_loss_r` 时，不开新风险（`CHAIN_LOSS_LIMIT`）。`profit_offsets` 为真时，盈利批次抵扣链亏损，默认不抵扣。
5. **事件前降险（`pre_event`）**：每条 `PreEventRule` 有：
   - `event_type`。
   - 窗口：预计时刻前 `before_seconds`、后 `after_seconds`。
   - `reduce_factor`。
   - `certainty_required`：为 `CONFIRMED` 时，只对已确认的日程生效。

   窗口内不开新风险（`PRE_EVENT_WINDOW`）。有持仓且该日程尚未处理过时，先把该日程记为已处理，再看止损：尚未到保本时，减到“持仓 × 缩减比例”，强制执行（`PRE_EVENT_REDUCE`）；已到保本时不减，之后也不再处理这个日程。

   保本的判定（`BreakEven`）：往返成本 = 当前价格 × 2 ×（`fee_rate` + `slippage_fraction`）。最后核验的止损（有收盘止损时取收盘止损），多仓不低于入场价 + 成本，空仓不高于入场价 − 成本。
6. **再入场门（`reentry`）**：`ReentryRule` 有 `cooldown_seconds` 和 `qualifying_inputs`。同向新风险要满足两条：止损后已过冷却时间，且出现合格输入。合格输入可以是 `NEW_CONTRIBUTION`（止损后注入的同向贡献），或 `BASELINE_RECONFIRM`（止损后带再确认标记的同向基线观测）。否则拒绝（`REENTRY_GATE`）。
7. **冻结批次数量 Q**：需要该方向有效的初始距离指令，且带风险比例。
   - 比例 = min（指令的风险比例，`max_risk_fraction`）。
   - 预算 = min（权益 × 比例，`object_loss_budget`）。
   - 每单位亏损 = 合约乘数 ×（初始距离 + 超出余量 + 价格 ×（`fee_rate` + `slippage_fraction` + `gap_fraction`））。
   - Q = 预算 / 每单位亏损，按步长向零取整。
   - 指令缺失时返回 `RISK_UNIT_DIRECTIVE_MISSING`；Q 为 0 时返回 `RISK_UNIT_QUANTITY_ZERO`。
   - `require_initial_distance` 表示必须有初始距离指令。
   - 冻结的批次写入风险批次表 `BatchRecord`。

成交后（`TrackBatches`）：

- 案例与批次关联，案例退出时批次结束，记录净盈亏、R = −净盈亏 / 预算（亏损为正 R），以及退出方式。退出方式包括：
  - 收盘止损：`CLOSE_STOP`。
  - 交易所止损：`VENUE_STOP`。
  - 保险止损：`INSURANCE_STOP`。
  - 目标调整：`TARGET`。
  - 未成交作废：`UNFILLED`。
- 以止损结束时，打开该方向的再入场门。
- 正的 R（亏损）计入判断链。

### 6.2 止损指令（`SubmitStopDirective`）

止损指令 `StopDirective` 的字段：

- 身份与种类：编号、对象、版本、种类（`POSITION_STOP` 或 `INITIAL_DISTANCE`）、方向。
- 价格与距离：触发价、触发价格类型、初始距离、风险比例、收盘止损价、收盘止损距离。
- 有效性：生效时刻与有效期。
- 来源与说明：来源模块、理由代码、模式（`VENUE` 或 `UPPER_MANAGED`）、超出余量。

写入权限由登记的写入方 `StopDirectiveWriterBinding` 决定：

- 字段：`binding_id`、`version`、`source_module`、`principal_id`、`object_id`、`environment`、`kind`、`can_write`，有效期为 `valid_from` 到 `valid_until`。
- 同一对象、环境、种类在任一时刻必须恰好只有一个有效的来源模块，且写入方身份匹配（`WriterAllowed`）。否则返回 `STOP_DIRECTIVE_WRITE_FORBIDDEN`。

受理时的检查：

- 版本只增；同一编号、不同内容时返回 `STOP_DIRECTIVE_CONTENT_CONFLICT`。
- 已生效且未过期。
- 风险比例不超过 `max_risk_fraction`。
- 工作负载身份提交的指令，还要读取交易层快照核验：触发价格类型是 `MARK` 或 `LAST`，且在品种支持的价格种类内；价格可用且不过期（`max_price_age_seconds`）；持仓止损方向与实际一致；触发价未被穿越；`VENUE` 模式的持仓止损还要符合价格步长。
- 公开身份提交的指令只记录为研究指令。

在决策中的使用：

- **持仓期间（`POSITION_STOP`）**：读取最新有效指令，生成保护计划（`StopPlanForDirective`）。与交易层已生效的保护不同时：目标等于当前数量，或原来没有保护计划时，下发“数量不变、只更新保护”的目标（决策带 `protection_only`）；已有调仓目标和保护计划时，数量和保护一起更新。
- **开仓（`INITIAL_DISTANCE`）**：用初始距离倒推数量（`SizeDirective`）；风险单位模式下用于冻结 Q。
- **没有有效初始距离指令时**：已有同方向目标的保护计划时沿用它；否则用噪声止损（第 6.3 节）。风险单位模式的新批次缺少初始距离指令时直接阻断（`RISK_UNIT_DIRECTIVE_MISSING`），不靠噪声止损开仓。
- **跟踪回执（`TrackStopReceipts`）**：根据交易层的保护事实，把已生效的上层止损记为 `LastEffectiveStrategyStop`。交易所条件单模式等交易所确认；上层管理模式核对交易层已受理的模式与声明。收盘止损价由 `CloseStopFor` 得出：上层管理模式用管理价；交易所条件单模式用指令的收盘止损价，或用“触发价 ±（初始距离 − 收盘距离）”。
- **指令过期**：保持最后生效的止损。

### 6.3 噪声止损（`NormalNoise`、`SizeAndStop`）

没有初始距离指令时：

1. 按完成与可用时间筛选后，取最近 `noise_window` + 1 根 K 线。其中有无效的 K 线，或相邻收盘间隔超过 `max_bar_gap_seconds` 时，噪声为未知（不跳过无效 K 线去补更早的）。
2. 每根的真实波幅比 = max（高 − 低，|高 − 前收|，|低 − 前收|）/ 前收。任一根超过 `max_noise_fraction` 时，噪声为未知。
3. 噪声 = 这些比值的 `noise_quantile` 分位数（线性插值）。
4. 止损比例 = max（`k_stop` × 噪声，`micro_distance`）。超过 `max_stop_fraction` 时不开仓（`STOP_DISTANCE_UNAPPROVED`）。
5. 触发价 = 价格 ×（1 ∓ 比例），按价格步长取整：多仓向上、空仓向下，即向当前价格靠近。
6. 数量上限 = `object_loss_budget` /（合约乘数 ×（|价格 − 触发价| + 价格 ×（`fee_rate` + `slippage_fraction` + `gap_fraction`）））。
7. 生成交易所条件单计划：滑点上限 = `slippage_fraction` × 10000 个基点，触发价格类型优先用标记价。名义金额低于品种下限、品种没有 `CONDITIONAL_PROTECTION` 或 `MARKET` 能力、或没有 `MARK`/`LAST` 价格类型时，不生成计划。

历史 K 线只在这里用于估计正常波动，不用于判断方向。

**已有持仓的风险修正（`CorrectActualRisk`）**：用已核验的策略止损计算实际风险（不含保险保护），超过 `object_loss_budget` 时，下发减仓目标（`ActualRiskTarget`）。当前持仓周期已有生效的上层止损，或有有效的持仓止损指令时，跳过这项修正。

### 6.4 收盘止损退出（`SubmitCloseExit`、`CloseExitNow`）

公开身份提交的退出请求，通过基本字段和写入权限检查后只保存为 `RESEARCH_ONLY`，不做下面的核验。工作负载身份的请求核验：

- 写入权限（按持仓止损的写入方）。
- K 线周期为 300 或 900 秒，K 线已完成且已可用。
- 收盘价与交易层的 K 线一致，误差在一个价格步长以内。
- 方向与实际持仓一致。
- 所依据的指令版本，是当前生效、且属于当前持仓周期的指令。
- 收盘价达到或越过收盘止损价：多仓收盘价 ≤ 止损价，空仓收盘价 ≥ 止损价。

通过后的处理：

- 请求为 `ACCEPTED`。调度器的下一轮在周期之外下发归零目标，不等下一个决策周期；前提是有有效价格样本、归属世代一致，且对象已有尚未到期的决策周期。不满足时等到下一个决策周期。
- 被交易层拒绝或过期时，回到 `ACCEPTED`，由下一轮调度重发。
- 自 K 线收盘起 30 分钟（`ExitRequestValidity`）仍未执行、同一批次仍在持仓时，记为 `EXPIRED` 并审计 `CLOSE_EXIT_EXPIRED`。
- 方向已变时，记为 `NOT_APPLICABLE`。

### 6.5 转基线（`TransferToBaseline`）

在同一事务里完成：

- 清除指定贡献的剩余影响，记账本原因 `TRANSFER`。
- 写入一条基线观测，守恒关联到转出量。

在副本上计算命令前后的合成值（`combinedNow`）。转换前合成值为零、方向改变，或变化超过合成规则 `transfer`（`TransferRule`）中的 `combined_tolerance` 时，整体拒绝。目标基线因子由 `factor_id` 指定。转基线不改变 Q 和保护。

## 7 决策周期与下发

### 7.1 周期（`DecisionCycle.Tick`）

1. **准备**：读取状态，按交易运行分组读取交易层快照。没有指定时刻的周期，在读完快照之后才盖时间戳，保证读到的内容在该时刻都已可用。快照时刻晚于周期时刻时，返回 `FUTURE_TRADING_SNAPSHOT`。
2. **逐个对象**：在一个事务里依次执行：
   1. 跟踪止损回执，校验账本。
   2. 更新实际与在途数量；归属世代或运行状态异常时，恢复状态标为 `RECOVERY_REQUIRED`。
   3. 更新价格样本。
   4. 更新案例与批次（第 8.1 节），修正实际风险，处理收盘止损退出。
   5. 未到周期就跳过。漏掉的周期记入 `SkippedCycles`，不补发。
   6. 生效或监测学习候选，失效撤回与更正的贡献，推进账本，注入新评分，评估学习。
   7. 合成，计算目标与止损。

   参数快照缺少 `w`、`g`、`h`、`eta`、`kappa`、`k_stop` 中任一键时，只推进账本，并记录一条保持目标的决策（`PARAMETERS_REQUIRED_UNSET`），跳过案例、批次、实际风险修正、收盘退出和合成。
3. **对每个对象的目标按顺序过一遍门控**：

| 门控 | 不满足时 |
|---|---|
| 对象非 `ACTIVE`、恢复状态非 `NORMAL`、交易层有风险锁、质量不合格、分层账本阻断、或有交付结果未知的目标，且目标会增加风险 | 保持当前（`RECOVERY_OR_PAUSE_OR_DELIVERY_BLOCK`） |
| 本周期有保护退出成交 | 不重新开仓（`STOP_CYCLE_NO_REOPEN`） |
| 合成路径下，暴露差小于无交易带（第 7.2 节） | 不调仓（`NO_TRADE_BAND`） |
| 非风险单位模式下，只有调整分量变化而档位未变，或距上次调整引起的调仓不足 `adjust_interval_seconds` | 不调仓（`ADJUSTMENT_LEVEL_UNCHANGED`、`ADJUSTMENT_INTERVAL`） |
| 风险单位模式下，差额小于 `band_ratio_of_unit` × Q | 不调仓（`UNIT_BAND_HOLD`） |
| 增险，且距上次调整不足 `cooldown_seconds`；或在不带合成的路径中，变动小于 `min_adjustment` | 不调仓（`ADJUSTMENT_COOLDOWN`） |
| 增险而保护计划无效或缺失 | 保持（`PROTECTION_PLAN_INVALID`、`PROTECTION_REQUIRED`）；已有在途数量且没有交付未知时，目标降到实际数量以撤销未成交部分（`PENDING_PROTECTION_INVALID_CANCEL_REQUIRED`） |
| 增险而交易层不支持新版保护接口 | 保持（`P1_LOWER_COMPAT_REQUIRED`）；减仓和归零不受影响 |

   强制减险、归零和收盘退出不受无交易带与冷却限制。

4. **组合约束**：同一交易运行的所有对象一起检查：
   - 总名义不超过 `portfolio_gross_limit`。
   - 净名义不超过 `portfolio_net_limit`。
   - 压力损失不超过 `portfolio_stress_limit`；压力 = |名义| × 止损比例。止损比例取本周期计算的止损；沿用已有保护计划时取 |价格 − 触发价| / 价格；没有止损时用 `max_stop_fraction`（`PreservedStress`）。
   - 每个风险组不超过 `group_limits` 中的对应值。
   - 交易运行中的其他暴露一并计入。反向时，总风险按旧仓与新仓的较大绝对值补计，并检查过渡期间净暴露的范围。

   现有风险已经超限时，先按比例缩减（`ACCOUNT_EXISTING_RISK_REDUCED`）。增险部分再用二分法求最大可行比例 α（`SharedProjection`），按 α 投影目标（`ACCOUNT_ALPHA_PROJECTED`）。数量步长使约束无法精确满足时，保持当前（`ACCOUNT_QUANTITY_STEP_RECONCILIATION_REQUIRED`）。
5. **时段占额（`Reserve`）**：每个增险目标占一个窗口额度。窗口由登记的时段计划决定；对象没有登记过计划时，按 `window_seconds` 自 `window_anchor` 切分。登记过计划、但当前时刻不在匹配版本的任何窗口内时，返回 `TIME_WINDOW_COVERAGE_REQUIRED`，不回退固定窗口。窗口的 `enforce_limits` 为真时，达到 `max_new_risk` 次，或窗口内亏损案例达到 `max_loss_cases` 个，返回 `NEW_RISK_WINDOW_LIMIT` 或 `LOSS_CASE_WINDOW_LIMIT`。亏损案例按案例的入场（占额）窗口计数，要求已退出、成本已知且净盈亏为负；迟到确认的亏损仍记回原窗口。
   - 时段计划 `TimeWindowPlan`：`plan_id`、`object_id`、`policy_version`、`source_version`、窗口列表 `windows`。每个 `PolicyWindow` 有 `window_id`、`start`、`end`、`enforce_limits`，相邻窗口首尾相接。
   - 计划由 `POST /objects/{id}/time-windows` 安装，安装后不可修改。
6. **生成决策与发件箱**：决策 `DecisionView` 写入各分量、理由码与输入哈希。输入哈希按完整输入计算，保存的是压缩后的输入（K 线、历史来源决策等改为引用摘要，生效贡献只保留六个字段）。有有效价格、且满足恢复、可减仓或保护更新的条件时，目标放入发件箱，状态 `PENDING`，有效期为 `target_ttl_seconds`；有交付未知的目标时，只有减仓目标可以入箱。

### 7.2 无交易带（`NoTradeBand`）

带宽 = max（`band_floor`，2 ×（`fee_rate` + `slippage_fraction`）+ |年化资金费| × `expected_hold_seconds` / 一年）。

年化资金费 = 费率 × 24 / 结算间隔小时数 × 365。资金费来源由配置的 `funding_source` 决定：

- 运行费率：运行所连交易所的当前费率。
- 参考费率：交易层提供的真实盘最近结算记录。

取不到时，使用合成规则里的 `funding_fallback_annual`。

### 7.3 下发（`Dispatch`）

调度和回报循环在每轮末尾执行下发：

1. 对 `PENDING` 或 `DELIVERY_UNKNOWN` 的目标，读取交易层的当前快照。
2. **已送达**：交易层的来源决策列表里已有这个决策，记为 `ACK`。
3. **增险或保护更新已被撤销**：对增险目标和 `protection_only` 目标，对象停用、有风险锁、运行异常、归属世代变化、来源事件被撤回、或止损指令失效时，记为 `EXPIRED` 或 `DELIVERY_UNKNOWN`（理由 `RISK_REVOKED_BEFORE_DELIVERY`）。
4. **已过期**：记为 `EXPIRED`。
5. **派发**：先在事务里冻结命令载荷（`Prepare`），标为 `DELIVERY_UNKNOWN`，再调用交易层设定目标（`Deliver`）。
   - 成功：`ACK`。
   - 交易层拒绝（4xx）：`REJECTED`，并记下原因。
   - 交易层不可用（5xx）：保持 `DELIVERY_UNKNOWN`，下一轮按同一载荷重试，交易层按幂等键去重。

## 8 案例、归因与学习

### 8.1 案例（`FeedbackCases`）

- **开立**：按归属者和交易对象，从成交建立持仓周期案例，冻结入场时的策略、参数和贡献快照。
- **观察期**：观察期长度 = clamp（`observation_multiplier` × `h`，`observation_min_seconds`，`observation_max_seconds`）。
- **退出**：持仓归零后进入观察；跨零时，把成交拆成平仓和新开两部分。
- **手续费币种**：手续费币种与结算币种不同时，案例记为成本未知。

### 8.2 标签（`LabelCase`）

- **时点**：τ 为最早贡献的生效时刻，标签时刻为 τ + `label_seconds`。案例要等到退出后的观察期结束、且过了标签时刻，才标注。
- **方向收益 y**：τ 到标签时刻的超额收益（有基准时扣除 `beta` × 基准收益）。
- **删失**：成本未知、有新的驱动事件介入、没有来源贡献，或 τ、标签时刻、退出、观察结束四个时点的价格不够新，或既没有基准也没有已验证的绝对价格代理时，记为删失。
- **方向标签**：|y| 不超过 `label_cost_band` + `label_noise_band` 时为 `NEUTRAL`；方向与 y 同号时为 `CORRECT`，否则为 `WRONG`。
- **强度误差**：预测强度 = `gamma` × Σ 初始量 × 方向，误差 = |预测强度| − max（0，方向 × y）。
- **生命周期**：累计方向收益达到 `lifecycle_fraction` 的时点记为 `h_proxy`。半衰期估计 `h_hat` = −`h_ref` × ln（1 − `lifecycle_fraction`）/ ln 2。

### 8.3 参数学习（`Propose`、`Activate`、`Monitor`、`Rollback`）

学习只在登记了学习清单（键为 `learning:<对象>`，含验证状态与要学习的参数）时运行：

- **可学习参数**：`w`、`h`、`kappa`、`eta`（`eta_anchor` 为 1 时不可学习，`PARAMETER_NOT_LEARNABLE`）、`k_stop`，以及合成规则里的分量与因子权重。当前参数必须为 `VALIDATED`；自动学习还要求市场状态恰好有五个维度且都不是 `UNKNOWN`。
- **证据**：来自成熟案例的敏感度和分层账本，要满足：成熟、可识别、无主要替代原因、已标定、置信度不低于门槛、非执行污染、非极端、非“盈利但判断错误”。每个独立样本组只取一条。
- **门控**：
  - 有效样本量、样本组数、重复次数。
  - 置信区间不跨零、死区。
  - 冷却。
  - 反向证据不弱于反向门槛；连续来回振荡则冻结。
  - 同一证据不能被两个候选使用。
  - 新值 = 当前值 ± 步长，限于上下界和漂移预算内。来源权重 `w` 跨零需要双倍的证据门槛。
  - 分量与因子权重：`ENABLED` 的权重只能向零降，不能增大或跨零；`SHADOW` 的正面证据走单独的晋升流程；`DISABLED` 不学习。
- **生效**：候选通过独立验证且改进不低于门槛后，在周期边界生成新的参数快照，对象改用新版本，候选进入 `MONITORING`。
- **监测失败**：回滚到父版本，候选的状态改为 `FROZEN`，`ROLLED_BACK` 记入其历史。
- **学习冻结**：策略的 `learning_mode` 为 `FROZEN` 时，候选照常计算，写入 `FrozenCandidates`，但不生成新快照，也不改变分量状态（`LearningFrozen`）。

### 8.4 分层账本（`SettleLayers`）

每个交易日按分量分摊：

- 盈亏和资金费，按决策中各分量在合成值里的有向份额分摊。
- 调仓手续费归入触发分量。
- 基线份额再按因子贡献比例分到各因子。
- 只记录分量按假设暴露记假设账务，与实际分列。

每日行在核对守恒后封存，最多保留 400 天（`LayerLedgerDays`）。不守恒时，对象的分层账本被阻断，决策不再增险（`LAYER_LEDGER_IMBALANCE`）。结算数量与交易层的实际数量不一致时，改用实际数量，记 `LAYER_QUANTITY_RECONCILED`，并阻断本轮增险。

### 8.5 研究工具

- **反事实（`CounterfactualRunner`）**：通过交易层的模拟接口执行单因素反事实，结果与实际账务分列。
- **研究验证（`ValidateResearch`）**：按登记的验证清单运行，不会把研究结果升级为生产参数。
