## 1 规划结论与执行原则

### 1.1 推荐实施路线

采用“数据先行、交易安全先行、固定参数先行、学习后启用”的路线。第一天启动合法可用数据的采集准备；先实现可回放的确定性核心和独立交易保护，再验证事件情绪是否具有扣除成本后的预测价值。通过回测、前瞻影子和模拟验证后，进入有人工值守的小额实盘；最后启用有界参数学习与受控扩容。

建议以 1 名量化研究负责人、1 名后端工程师、0.5 名测试与运维人员作为估算基线。固定参数有限实盘目标窗口为第 24～28 周，完整受控自适应版以 28～40 周作为总体规划区间；这是满足数据和验收条件时的工程排程，不是承诺实盘盈利或强制上线日期。单人配合 AI 时，按每周 4.5 个有效人日折算约 52～75 周，并另计无法并行的样本等待；AI 能否压缩工作量须在前两周实测后重估。第 12 章给出工作量和依赖。

最终系统必须包括事件理解、去重、提前计价、情绪池、时间衰减、价格兑现、状态识别、仓位控制、止损、全局风险、交易执行、案例观察、归因、有界学习、验证、监控及恢复。首次实盘冻结参数只是实施顺序，不删减用户要求的最终能力。

### 1.2 完成定义与明确边界

“上线完成”指版本可重复部署、交易链路可对账、独立保护可用、研究证据通过、实际成本已校准、值守与恢复演练通过、上线记录和限额签署完整。不能以“API 已下单”“回测盈利”或“连续几天赚钱”单独宣称完成。

首期限定一个交易场所、一个合约、一个独立策略账户、一个净持仓方向。系统支持做多和做空的研究及实现，但每个方向分别通过验证后才可启用；单向持仓模式不等于只能做多。暂不做跨所套利、多品种组合、加密币抵押、组合保证金、高频做市或模型自行修改代码。未开放的交易时段仍采集数据并运行风控。

本文标记规则：F 表示本次核实的事实；P 表示建议的实施基线；D 表示必须在指定阶段关闭的待决项。P 可以用于设计和模拟，只有经阶段负责人确认的配置版本才能用于实盘。资料核实日为 2026年9月22日（日本时间），对应 UTC 2026年9月21日；外部规则须在开发与上线时再次核对。

### 1.3 失败时的退出路线

如果账户无法合法使用产品、拿不到合格的时点数据、保护订单能力不足或核心假设未获支持，应停止推进实盘。保留数据、回放、监控和研究成果，登记“不通过”或“证据不足”；后续重新立项验证，不以增加杠杆、改变测试区间或反复试参数弥补证据缺口。

P：研究主周期为 1 分钟行情、5 分钟策略评估，事件到达后可触发额外评估；只允许在完整、可用的数据时点决策。交易回报和风控按事件立即处理，不等待策略周期。先研究小时级至 1～3 个美股交易日的影响窗口，窗口是否适合必须用数据验证。

P：首个实盘版本只在获准的美股常规时段增险，盘前、盘后、隔夜和周末分别作为独立扩展项。初期默认收盘前按配置停止开仓并计划归零；未能归零时维持保护和告警，不能假装已平仓。时间表使用 America/New_York 时区和交易日历处理夏令时、节假日及提前收市，交易所时段接口用于交叉核对。

P：独立账户、USDT 单资产、单向持仓，优先逐仓；禁止自动追加保证金。逐仓或所需订单语义若不支持，停止该上线方案并重新评审，不能自动切换全仓。账户设置杠杆与策略名义敞口/净值上限分别约束，不把低设置杠杆当成风险控制的全部。

### 4.2 必填的风险配置

以下字段在研究前可保留空值，进入模拟交易前必须赋值并冻结，进入实盘前由资金负责人确认。缺值、负值、上下限倒置和过期配置均阻止增险。数值由承受损失、流动性、成本和压力测试共同决定，不在本规划里凭空指定实盘资金规模。

| 配置组 | 必填字段 | 校验与责任 |
|---|---|---|
| 资金 | 实盘本金 C、试运行损失预算 B、USDT 可用储备 | 资金负责人；B 不得因亏损自动增加 |
| 敞口 | 名义上限 N、净值比例上限、单笔数量、未完成订单上限 | 风险负责人；包含最不利待成交敞口 |
| 损失 | 每笔风险额、日亏损限额、总回撤限额、连续亏损暂停阈值 | 风险负责人；以含未实现损益及费用的净值衡量 |
| 保证金 | 模式、设置杠杆、保证金储备、强平距离警戒 | 工程核验，风险负责人确认；分档动态重算 |
| 市场质量 | 价差、盘口容量、基差、报价年龄、资金费预算 | 研究与工程共同校准；按时段分层 |
| 保护 | 止损距离边界、保护确认时限、退出最大等待、残仓策略 | 安全测试通过；不能放宽原仓位止损 |
| 运营 | 值守窗口、日界线、告警联系人、恢复签署人 | 建议风险日界线 UTC 00:00；改变需专门迁移 |

P：日亏损或总回撤触限后锁定增险、撤销增险订单，并启动受保护的退出流程；锁定持久化，禁止重启或跨日自动解除。恢复需新风险版本、对账与人工检查。若用户选择触限后保留仓位，必须作为 DEC-06 的显式替代政策重新测试。生产与模拟使用同一个风险函数，环境只改变适配器和限额。

### 4.3 数量、损益与账务口径

按当前合约单位计算：名义敞口为数量绝对值乘以单位乘以参考价格；线性合约价格损益为带方向数量乘以单位乘以成交价差。单位需从有效合约规格核实并版本化。风险数量取以下约束的最小值：信号目标、单笔损失预算可承担数量、名义限额、保证金可用量、盘口容量及剩余日风险预算，并向不增险方向取整。

单笔计划损失包括止损价差、双边费用、保守滑点、预期资金费与跳空储备。它是规划上限估计，极端行情可能超过；强平不是止损替代。风险引擎须校验止损与强平边界之间留有压力缓冲。

净值以交易所账户权益对账，分解为现金流、已实现损益、未实现损益、佣金、常规资金费、特殊分红资金费及其他调整。记录结算资产与换算时点，日损益排除外部净流入。未能归类的收入不得默认为策略收益，转入待核账并阻止扩容。

## 5 目标架构与技术决策

### 5.1 部署结构

P：首期采用模块化单体加隔离进程：数据采集与归档、研究/AI 工作者、确定性策略核心、独立风险与执行进程、运维控制台。交易密钥仅在执行进程可用；AI、研究、网页和新闻处理均无交易权限。风险与执行通过事务性订单意图队列交互，风险拒绝具有最终优先级。

数据流为：行情/新闻/日历 → 原始归档 → 时点规范化 → 事件评分 → 情绪账本 → 目标仓位 → 风险批准 → 订单意图 → 执行 → 交易所回报与对账。案例、标签、归因和候选参数从这条链路读取不可变证据，不能逆向修改历史交易。

运行一台交易主机、一台独立监控与恢复主机，数据库具备独立备份。初期恢复由人工接管，禁止两个主机同时发单。需要自动接管时，必须先实现可证明的旧主机隔离、单写者所有权和恢复对账；仅有数据库租约不足以阻止网络分区中的旧主机继续交易。

### 5.2 技术栈建议与选型验证

以下是项目设计选择，不依赖“最新版本”承诺。WP-03 选择仍受维护的稳定版本，锁定依赖与镜像摘要，并检查许可和安全更新。框架是否适合通过最小闭环验证，不以功能清单直接认定兼容。

| 层次 | 建议方案 | 采用理由及限制 |
|---|---|---|
| 核心与研究 | Python、类型约束、十进制金额类型 | 复用数学核心；浮点计算与交易精度边界分离 |
| 持久化 | PostgreSQL、事务 outbox、追加式业务账本 | 原子记录风险决策与意图；不依赖易失内存队列 |
| 历史数据 | Parquet、按日期/来源分区、对象存储 | 原始与规范化层分离；清单和哈希可复现 |
| 交易接入 | 官方文档对应的薄适配层、HTTP 与 WebSocket | 针对 TradFi、条件单和错误语义做契约测试 |
| 控制台 | FastAPI 与轻量网页界面 | 展示状态和审批；不把交易权交给浏览器 |
| 部署 | Linux 长期支持版、容器、受控发布脚本 | 先验证重启、日志、时间同步和回退 |
| 观测 | 指标采集、日志、告警、独立心跳探测 | 业务指标与系统指标并行，链路中断仍能告警 |
| 测试 | 确定性回放、属性测试、模拟交易所、故障注入 | 同一策略核心贯穿历史、影子、模拟和实盘 |

P：首期不引入分布式微服务、复杂消息集群或 Kubernetes。若数据库队列吞吐无法满足压力测试，再以证据调整架构。AI 模型供应商通过抽取质量、延迟、成本、许可及数据保密评测选择，所有输入输出保留版本；不把模型名称绑定到数学核心。

### 5.3 数据对象与模块契约

每个消息统一包含 schema_version、业务 ID、来源、原始发生时间、首次可用时间、接收时间、关联 ID 和内容哈希。时间使用 UTC，展示可换时区；金额、价格、数量和单位不可混用。模式升级支持旧版本重放，未知必填字段拒绝而非猜测。

| 对象 | 核心内容 | 唯一性与不变量 |

### 5.4 环境与安全隔离

开发、回测、测试网、影子、模拟和实盘使用不同配置、数据库与凭据；默认运行模式为研究。启动需同时通过环境标识、账户指纹、配置签名、品种白名单和风险上限检查，单个环境变量不能打开实盘。部署服务账户无提币或转账权限，API 使用最小权限及 IP 限制；密钥来自受控密钥存储，不进入源码、提示词、日志或文档。

生产与研究网络隔离；所有外部新闻内容作为不可信输入。模型输出必须符合结构模式、数值边界和证据引用，不能产生可执行指令。保留依赖清单、漏洞修复流程、登录审计和双因素认证；账户与密钥轮换先在模拟环境演练。

### 6.2 时点正确性与质量闸门

交易可用时间取来源发布时间、实际首次接收时间以及必要处理完成时间的约束结果；历史试验加入测得的延迟分布。只有事后爬取时间、没有可靠首发记录的文章，不能伪装成低延迟历史信号。保存供应商补发与更正，不对旧数据原地覆盖。

逐日输出覆盖率、缺口区间、异常价、重复率、时钟偏差、新闻延迟、模型失败率、时段分类和公司行动核对结果。缺失不是零事件或零波动。市场休市与采集故障分开标记；无有效报价时禁止生成虚假平稳行情。

P：回放输入由数据清单、哈希、规格版本、特征版本和代码摘要固定。研究结果可定位到原始证据。复权与未复权价格不得混用；当前成分股及权重不得倒灌历史事件影响计算。历史订单簿缺失时使用保守成交区间，不宣称精确逐笔回测。

### 6.3 研究假设与实验顺序

第一批仅研究三类事件：重要半导体企业财报/指引、明确影响产业链的监管或供给事件、预先登记的宏观政策事件。实体到行业的关联强度按当时成分及经济关系确认。扩充类型必须证明独立增益，不能用更多因子掩盖初始假设失败。

实验按顺序登记：事件原始方向是否有信息；去重与未预期程度是否改善；时间衰减是否优于固定窗口；价格兑现是否在时点正确的前提下改善；仓位滞回是否减少成本；风险约束是否改善尾部损失；归因门控是否减少错误更新；有界学习是否优于冻结参数。它们是原规格 H01～H08 的实施实验，不重新定义原假设编号；WP-04 将每个实验映射到原假设，特别补齐情绪强度单调性、类型兑现差异及漂移诊断。

每次实验必须登记主指标、经济上最小可接受改善、时间窗口、事件组、比较基线、成本假设、参数搜索范围和失败标准。使用现金基线、风险匹配的简单价格策略、冻结情绪模型及逐项消融。做空方向不能借做多方向的结果直接准入。

### 6.4 三层验证与统计门槛

第一层用较长 ETF/行业历史验证事件与生命周期假设；第二层用真实合约历史验证成本、基差、资金费和风险适配；第三层用模型冻结后的前瞻数据验证可用延迟与真实决策。三层分别报告，禁止拼接成未经说明的长年合约业绩。

训练、验证、测试保持时间顺序，按事件族分组，并清除跨窗标签重叠与设置隔离期。测试集封存，仅在版本冻结后运行一次。AI 可能记忆历史结果，历史抽取评估必须披露污染风险；前瞻试验在输入到来前冻结模型和提示词。

P：主收益指标为扣除全部成本、按风险预算归一化的净收益改善；同时报告回撤、尾部损失、换手、资金占用、滑点、独立事件数、未知比例和各时段结果。使用适合相关样本的区块重采样及候选数量控制；改善区间跨越无效区域时结论为证据不足。WP-04 先按最小效应与统计功效估算所需样本，再设前瞻观察期，不能事后选择门槛。

工程排程预留至少 4～6 周前瞻观察、至少 4 周模拟和至少 4 周有限实盘观察，但这些是时间下限安排，不是充分性标准；缺少独立事件、宏观窗口、方向或市场状态覆盖时继续观察。订单条数、重复转载和同一事件多次交易不得充当独立样本量。

## 7 策略、归因与学习实现

### 7.1 确定性交易核心

按原规格实现纯业务计算模块：事件标准化与去重 → 评分乘数及上限 → 情绪注入 → 时间衰减 → 方向价格高水位及兑现预算 → 失效处理 → 状态与辅助因子 → 仓位滞回 → 风险投影。计算不读取系统隐含当前时间、不临时访问外部服务；时钟、输入快照和随机种子均显式传入。

先用原规格数值夹具建立验收，再加入长序列回放。任何模式必须复用同一计算核心；禁止为实盘另写一套未对照的情绪公式。所有单位、零值、边界、累计误差与舍入定义进入 ADR。信号解释至少显示贡献来源、残余情绪、兑现与衰减、触发阈值、目标量及风险裁剪原因。

SOXL 特有的兑现研究必须分解行业普涨、ETF 路径影响、汇率和合约基差。若无法从合约价格中可靠区分事件兑现，则保留“不确定”标签，冻结相关学习；不强行从价格变化倒推事件一定正确。

### 7.2 AI 事件服务

AI 仅生成结构化候选事件，包括事件类型、实体、方向、幅度档、可靠度、未预期程度、证据片段、来源和不确定项。评分由结构校验与固定规则约束。无证据、超界、格式错误和超时进入隔离队列，不重试到得到想要的方向。

对同一原文和模型版本缓存结果，记录 token 成本与耗时。重试不能形成新事件；供应商切换和模型升级作为版本变更验证。建立人工标注集评估分类、方向、事实一致性、去重和弃权质量；标注人员看不到未来收益，分歧单独登记。

### 7.3 案例、归因与标签

以实际持仓周期建立案例，关联部分成交、加减仓、退出、费用和退出后的固定观察窗口。止损后继续观察，区分行情反转、信号幅度、兑现速度、执行误差、风险约束和外部异常。多事件重叠时保留共同驱动组，不把不可识别的单事件收益作为精确标签。

成熟条件由观察窗口、数据完整性和公司行动处理共同决定。删失样本仍计入覆盖率；反事实路径独立保存，不进入真实净值。案例标签与收益报告可修订，但必须保留旧版本和修订理由，已经使用的学习证据不能静默替换。

### 7.4 学习分四级启用

L0：全部参数冻结；完成案例和归因采集。L1：只生成学习候选，记录本来会调整什么，不改变交易。L2：候选通过独立验证、影子比较和人工发布后生效。L3：只有预先授权的白名单参数，在满足门控、固定步长、冷却、累计漂移边界和回滚条件时才能自动发布。

首批最多开放一个经识别性验证的参数族。硬限额、日亏损阈值、杠杆、账户模式、交易权限与生产模式永远不属于可学习参数。旧情绪贡献及旧仓位遵循既有冻结规则；新参数只在规定边界前瞻生效，不能扩大旧仓位风险。

每个候选保存独立证据、有效样本量、单参数差异、冻结对照、试验成本、结果区间和拒绝理由。同一证据不得反复驱动更新。漂移、连续反向更新、归因可信度下降或性能恶化时冻结学习并回退参数版本；回退不删除历史决策。

## 8 币安交易接入与持仓保护

### 8.1 第一阶段必须验证的能力

WP-02 形成能力矩阵：公开数据、时段、账户权限、独立账户、保证金模式、仓位模式、账户费率、杠杆档位、普通订单、条件订单、只减仓、撤单、成交查询、资金费与收入、用户回报、断线恢复、历史查询保留范围。每项标为“文档支持、目标环境实测通过、不支持、未知”之一；文档支持不能直接当成目标环境通过。

官方交易接口对普通订单与条件订单提供不同能力，保护单需覆盖 algoOrder 的创建、查询、撤销与触发后订单关联。参数组合按当前文档与目标账户测试；closePosition、quantity、reduceOnly 和仓位模式的限制不能依靠默认值猜测。[币安交易接口](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/trade)

测试网是否提供 SOXLUSDT 和相同 TradFi 机制尚未核实。若不提供，以模拟交易所验证专属逻辑、测试网其他合约验证通用协议、真实公共流验证行情；差异必须列入残余风险，并在所有安全门通过后，使用专门批准的最小生产联调额度补齐。不能宣称替代标的测试等于目标合约实测。

### 8.2 订单状态机与对账

状态机至少区分准备、已持久化、发送中、已受理、部分成交、全部成交、撤单中、已撤销、拒绝、过期与结果未知；“HTTP 请求失败”不等于“订单未成立”。部分 503 响应可能表示执行结果未知，必须先查询及核对回报，避免重复发单。[官方错误与重试语义](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/general-info)

P：订单意图及风险决策在同一事务写入，发送前取得单写者所有权。客户端 ID 保持稳定；进程在发送与落账之间崩溃时，恢复程序先查单再决定后续。累计成交、手续费和持仓依据外部业务 ID 去重；系统承认网络交付可重复，通过幂等和对账实现业务不重复。

风险敞口包含实际持仓及可能成交的未完成、发送中和未知订单。多转空时先减仓并确认归零，再创建反向增险意图；撤单失败或未知时不立即补发反向仓。私有流作为快速更新源，定期查询作为恢复与一致性核对；二者冲突进入风险锁定。

### 8.3 保护单与紧急退出

每次成交后立即建立或调整交易所侧保护，并独立查询确认；本地记录“已发送”不算受保护。支持时优先使用已验证的全平或仅减仓保护语义，保护方向、触发价格、数量、有效状态和实际仓位须持续核对。触发后还需确认成交与残仓，不能把“已触发”当成“已平仓”。

保护触发参考价格和 priceProtect 选择写入 ADR：标记价有利于对齐保证金风险，但可能滞后于可成交价；价差保护也可能延迟触发。通过极端基差场景比较后冻结方案，不能默认开启即更安全。市价保护仍可能滑点或无法即时成交，须配备独立退出监测。

入场与保护通常存在非原子窗口。P：将“成交确认到保护可查询确认”目标设为 p99 不超过 2 秒，超过 5 秒视为严重异常并立即禁止增险、尝试仅减仓退出；这些是待压测的工程目标，交易所异常时不保证达成。持续无法安装保护时禁止继续运行该实盘方案。

调整保护时先验证新保护可用再撤旧保护；若接口不允许并存，按已验证的安全替代流程执行，并记录无保护窗口。撤销全部订单必须区分增险单和保护单。死亡开关、定时撤单及人工停止都要验证不会留下裸仓；停止新交易不等于撤销持仓保护。

### 8.4 限流、时钟和异常恢复

分别预算市场查询、订单、账户查询与紧急减仓的请求额度。触发限流后退避并降低非必要查询，保留退出能力；不得不断重试造成封禁。时钟偏移超阈值时停止签名增险请求；恢复时补齐订单、成交、资金费和持仓，再重建策略状态。

交易所不可达时保留已在交易所成立的保护、冻结新增并告警；不能承诺本地一定能平仓。恢复后先确认真实仓位及订单，旧未发送意图默认失效，不重放过期交易。人工在交易所操作须进入审计并被对账识别；发现外部仓位改变后策略暂停，避免自动补回人工减掉的仓位。

## 9 测试、安全与性能目标

### 9.1 分层测试策略

单元与属性测试覆盖数学不变量、风险单调性、精度、去重和状态转移；契约测试覆盖真实接口字段、错误语义及枚举变化；集成测试覆盖事务、回报、重启和对账；回放测试验证同输入同版本结果一致；故障注入验证断流、时钟漂移、重复回报、网络分区、数据库不可用与满盘。

所有测试记录输入、可用时间、预期、实际、版本和证据位置。收益试验与安全测试分别出结论。P0 安全失败、未关闭的严重缺陷或无法解释的账差都阻止实盘，不以总体通过率抵消。低优先级缺陷需有影响范围、临时控制和修复期限。

### 9.2 工程服务目标

下表为建议验收目标，适用于单品种、非高频系统。WP-03 用目标部署地区和真实数据测量；不达标先修改架构或收窄交易窗口，不能无记录地放宽门槛。交易所不可达属于外部事件，仍计入业务可用性，同时单独归因。

| 指标 | 建议目标 | 失败行为 |
|---|---|---|
| 核心计算延迟 | 冻结输入到风险决定 p99 ≤ 500 毫秒 | 暂停增险，保留快速风险处理 |
| AI 事件处理 | 正常负载 p95 ≤ 30 秒；超过 60 秒标记迟到 | 重新校验可用性，不追溯成交 |
| 市场数据年龄 | 报价超过 5 秒或序列有缺口即不可用于增险 | 补快照并重建；分清源时段与故障 |
| 账户状态确认 | 私有流断开即暂停增险；至少每 30 秒主动核对关键状态 | 未知订单不补发；减仓通道继续 |
| 时钟偏差 | 警戒 250 毫秒；超过 500 毫秒阻止增险 | 修复同步并复核签名请求 |
| 保护完整性 | 所有持仓受保护；例外窗口按第 8.3 节处置 | 严重告警、退出、事故记录 |
| 告警时效 | 严重故障 30 秒内送达；值守 5 分钟内响应 | 无响应进入预定降险流程 |
| 状态恢复 | 单进程恢复 ≤ 10 分钟；主机恢复目标 ≤ 60 分钟 | 未对账绝不恢复发单 |
| 数据恢复 | 已确认业务意图不丢；数据库备份恢复点目标 ≤ 5 分钟 | 缺失部分从交易所补账，否则锁定 |
| 压力与容量 | 预估峰值 10 倍输入运行 1 小时无无界积压 | 降载研究/AI，保护执行资源 |

### 9.3 测试发布门槛

P：所有适用 AC 和 TC 必须通过，关键分支有边界与故障用例；不以代码覆盖率作为唯一门槛。至少完成一次从备份恢复、一次主机失联、一次交易所延迟回报、一次保护失败、一次人工紧急退出、一次密钥轮换演练。实盘前连续模拟运行期不得出现未解释重复成交、裸仓超时、风险绕过或账差。

压力场景包括行业急跌、ETF 大幅跳空、盘口消失、资金费骤变、USDT 偏离、休市模式切换、除息只减仓、拆并股、强平警戒、ADL 和产品暂停。场景不需要预测概率才能测试，但必须区分真实历史、合成假设和交易所可验证行为。

## 10 生产部署与运营

### 10.1 基础设施与发布物

生产选址以账户规则允许、网络质量稳定及可维护为前提，不按“最低延迟”单独决定。WP-03 测量往返延迟、丢包、断线恢复及时钟同步。部署主机只开放必要端口，数据库不直接暴露公网；定期验证备份可读、容量余量和恢复耗时。

每次发布交付代码摘要、依赖锁、容器摘要、数据库迁移、配置签名、模型/提示词版本、合约规则快照、数据清单、测试报告、已知问题、部署步骤与回退步骤。生产不得使用浮动标签和未固定的模型配置；供应商强制变更时进入新版本验证。

部署顺序：保存状态 → 禁止增险 → 核实保护与未完成订单 → 备份 → 向后兼容迁移 → 部署 → 只读自检 → 全量对账 → 核验限额和时段 → 恢复获准模式。不得在有仓位时随意重置数据库。破坏兼容的迁移优先安排在已确认空仓窗口。

### 10.2 控制台与人工操作

控制台必须显示环境、账户指纹、当前阶段、最后健康时间、持仓及待成交敞口、保护状态、日损益/总回撤、保证金风险、可用行情、事件情绪、当前参数和最新告警。显著区分“停止开仓”“受保护平仓”“冻结学习”“恢复运行”。

人工修改额度、启用方向、开放时段、发布参数和切换生产模式必须有操作者、原因、前后值与生效时间。危险操作显示当前真实仓位及后果；不会因页面刷新重复执行。紧急停止优先可用，但不自动删除保护订单。

### 10.3 日常工作与事故等级

每日开仓前检查账户、合约状态、交易日历、公司行动、数据质量、资金费、保护通道、备份和告警。收盘或获准窗口结束后核对成交、费用、持仓和现金流，审阅未知事件及学习候选。每周检查数据许可、外部规则变化、依赖安全、容量、样本覆盖与模型漂移；每月做恢复演练和成本复盘。

SEV-1：裸仓超时、未经授权增险、重复成交、密钥泄漏、持仓严重不一致或触及强平警戒。立即冻结增险与学习，启动退出/保护流程并通知值守。SEV-2：关键行情或账户流中断、保护质量下降、规则无法解析。停止受影响模式，核对后恢复。SEV-3：非关键报告延迟或研究任务失败，修复时不占用执行资源。

严重事故恢复至少要求原因定位、修复验证、补账、保护检查、回归用例和责任人签署。无法联系值守时不新增风险；24/7 实盘模式需覆盖 24/7 的责任安排。仅有单人白天维护时，首期使用明确受控的持仓窗口，不能假定系统自动运行就等于有人负责。

### 10.4 退出与项目停止

退出顺序为冻结新增、撤销增险订单、核对实际仓位、受保护减仓、确认归零、处理条件单残留、保存完整账本、关闭交易权限。若交易所不可达则进入事件处置，持续核对并保留保护，不能将进程停止作为退出完成。停止研究或下架策略后仍保留审计、成本与事故记录。

## 11 阶段准入与实盘投放

### 11.1 阶段与准入门

保留原规格 R0～R4 的含义；本计划增加准备门 G0，细化各阶段退出条件。尚未过研究门的实时记录称“数据采集/工程观察”，不能标为已经获准的 R1。阶段转换只能依证据，时间表到期不自动升级。

| G1 | R1 前瞻影子 | 核心假设得到足够支持；无泄漏回放通过；冻结模型与参数；公开实时流质量合格 |

### 11.2 有限实盘的三个台阶

台阶 A 为连接与记账验收：使用当前规则允许且处于批准损失预算内的最小订单，验证开仓、成交、保护、减仓、资金费、费用与归零。若最小有效订单已超过风险预算，则不做生产联调。不会为测试故意触发强平或制造极端损失。

台阶 B 为固定参数策略试运行：仅开放获准方向、时段及容量，持续对比实时模拟与真实成交；禁止在线学习发布。净收益、滑点、漏单、保护时延、账差和人工干预同时评估。观察期至少按第 6.4 节安排，达不到统计覆盖继续观察。

台阶 C 为受控扩容及学习试运行：先完成 G4，再按批准的容量台阶扩大；一次只改变额度、时段、方向或参数族中的一项。下一台阶前重新估算盘口冲击和保证金压力，发生严重偏差退回前一台阶；不能只因盈利而自动加仓或追加本金。

每个台阶记录起止时间、资金和名义上限、最大允许试验损失、模型版本、值守人、停止条件和验收结论。累计实盘试验损失预算不因台阶切换重置。

### 11.3 上线检查清单

上线记录至少逐项确认：账户与产品可用；条款由账户持有人确认；品种及模式正确；资金/名义/损失上限已签署；所有保护单能力实测；订单与收入对账通过；数据与日历正常；公司行动已处理；密钥与网络权限正确；告警可达；值守在场；备份可恢复；代码和配置已冻结；回退步骤可执行；P0 缺陷清零；研究与模拟证据足够。任何一项未通过均记录阻塞人和关闭方式。

## 12 工作分解、里程碑与关键路径

### 12.4 关键路径与并行边界

关键路径 A：账户/数据可行性 → 时点数据 → 事件与情绪核心 → 无泄漏研究 → 前瞻证据 → 模拟 → 小额实盘 → 受控自适应。关键路径 B：目标合约能力 → 风险账务 → 普通/条件单保护 → 故障恢复 → 上线。只有 A、B 同时到位才可进入 G3。

可并行的是数据采集与工程骨架、研究与执行安全、控制台与案例归因；不可并行替代的是未成熟标签与学习、未知订单与补单、未确认保护与扩大持仓。每两周复盘剩余工作量、事件样本、阻塞天数和预算消耗；成本或工期超过基线 20% 时重估范围及排期，不默认提高风险求进度。

## 14 人员、费用与资金安排

### 14.1 责任分工

Q 对假设、数据时点、参数、评估和归因负责；E 对正确接入、精度、订单、账务和可部署性负责；T 对独立验证、恢复、告警和发布证据负责；O 对本金、损失预算、账户条款、最终限额与扩容负责。编写关键交易代码的人不能成为其唯一验收人。

如果只有一名开发者，AI 可辅助但不算独立风险责任人；上线前安排外部工程/交易系统复核，并将复核工作计入预算。用户不必审阅所有实现细节，但必须能从控制台和报告确认实际风险、当前状态、停止与恢复后果。

### 14.2 研发与运营预算模型

以下金额是预留预算区间，币种为人民币，不是供应商报价，也不包含交易本金、交易损失、税费或收益承诺。数据授权费用可能显著超出区间；WP-02 获取实际报价后更新。人员报价由用户所在地和合作方式决定，不在未知条件下虚构总包价格。

| 费用项目 | 规划口径 | 预算管理 |
|---|---|---|
| 研发人力 | 231～336 人日 × 实际综合人日成本 | 若按 1,500 元/人日示例，为 34.65～50.40 万元；仅为算术情景 |
| 预备金 | 已核定研发预算的 20%～30% | 变更、接口返工、安全复核；动用须记录 |
| 服务器、数据库与备份 | 1,000～3,000 元/月预留 | 先测容量；生产与研究分开控制资源 |
| 行情、新闻及日历许可 | 1,000～10,000 元/月预留 | 时点历史和机器处理权优先；不足则重预算 |
| AI 推理与标注 | 500～3,000 元/月预留 | 去重、缓存和日预算；按事件覆盖评估价值 |
| 告警与辅助服务 | 200～1,000 元/月预留 | 主通道和备用通道分别演练 |
| 运营费用合计 | 2,700～17,000 元/月预留 | 按供应商报价替换；高频历史采购另计 |
| 交易成本与试验损失 | 单独登记佣金、滑点、资金费、分红调整和 B | 不混入软件成本；达到 B 停止试运行 |

开发期间的服务支出为各月实际开通费用之和，不必从第一月购买完整生产规格。自有人员的现金支出可能较低，但人日投入仍须记录。不得通过降低数据时点质量、删去保护能力或省略恢复测试来压缩成本。

### 14.3 资金上线前的约束

实盘本金 C、可接受试验损失 B 和最大名义 N 均由 O 确认，并用压力测试检查兼容性。先验证当前最小订单及保证金需求是否允许在该预算内试验，再确定台阶金额。交易所外的资金储备不应由程序自动转入；扩容单独确认并记录新的生效上限。
