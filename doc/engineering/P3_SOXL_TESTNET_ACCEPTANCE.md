# P3 SOXLUSDT 测试网联合验收协议

2026-10-12；code-only 方法试验，基线 v2.5.3。本文先于测试网写操作提交。只用 Binance U 本位合约**测试网虚拟资金**，不连接正式账户、不切换生产运行、不批准 LIVE。

## 目的

T3-07（产品账务及参考价）、T3-09（额度/保护）、T3-14（故障残仓与恢复）此前只有只读账户和文档证据：SOXL 正式规格与清算程序支持“API 数量按 SOXL 份额、线性换算系数 1”的解释，但没有本产品的实际成交、费用和保护触发证据（见 [产品证据](P3_VENUE_VERIFICATION.md)）。P1 的 Go 测试网完整套件已在 ETHUSDT 上通过 25 项（见 [P1 记录](../progress/P1.md)）；本轮以同一已验收工具、对目标产品 SOXLUSDT 运行一次，取得账户事实。

## 方法

- 工具：既有 `runtime/go-bin/testnet-acceptance`（P1 已发布设计与实现，不改代码），参数 `--symbol SOXLUSDT --max-notional 100 --authorize-testnet-orders`，原生 PostgreSQL 来自 `runtime/native-pg`。工具固定官方测试网 `https://demo-fapi.binance.com`，要求整个测试账户平仓且无挂单，否则在写操作前拒绝。
- 乘数：工具对诊断标的使用乘数 1。若乘数解释错误，P1 账本按乘数 1 计算的名义、费用与盈亏将与交易所 userTrades/钱包变化不一致，账务核对项会失败；因此本轮可以用账户事实检验该解释，而不是预设它成立。
- 检查：沿用 25 项——挂撤单、回执丢失后原 ID 查询且不重复提交、市价成交、物理止损覆盖与重叠替换、交易所止损实际触发和退出成交、费用/盈亏/钱包核对、停机后独立 REST 应急减仓、重启拒绝提前恢复、导入回执与 epoch 提升、审计写失败与 NOLOGIN 阻断。
- 次数：完整运行一次。失败时保留 failure-snapshot.json 与报告，执行工具自带的受限清理并确认平仓；不立即重跑以掩盖失败。若失败原因属于环境（如测试网临时错误），记录后再决定是否另起一轮，并在结果中如实列出全部轮次。

## 结论边界

通过只说明：SOXLUSDT 在测试网上可由 P1 执行与保护链路下单、止损、应急减仓和恢复，且账务与乘数 1 一致。不证明正式账户的产品协议、实际费率政策、资金费结算、流动性、LIVE 延迟或 4000/400 USDT 额度的适用性；T3-09 的业务参数与 DEC-06 仍未决。报告与回执只存忽略的 `runtime/p1-go-*`，公开记录只含检查结果、汇总数值与哈希。
