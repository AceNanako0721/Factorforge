# 语言选择与模块边界

确认日期：2026-10-10；设计基线：[v2.1.15](../v2.1.15/index.html)，Change-Type: design。本文为持续工程约定；发布设计正文以配对 HTML 为准。

用户澄清：“越上层没有必要统一成go。除了go，像ts都随便用的，别用python就行，本身我要求各层以接口相接就是方便模块化。”

## 已确认规则

- 禁止 Python；活跃生产/开发链路不引入 Python 源码、解释器、子进程或必需 Python 服务。历史冻结资料保留且不执行。
- 不要求全项目统一 Go。上层可使用 TypeScript/JavaScript 等非 Python 语言，包含后端与独立模块，不限前端；依模块适配性、可复用实现和部署成本选型。现有 P1/P2 Go 核心及已实现上层模块保留，本次不要求重写。
- 三层不变：P1 独立，P2 只依赖 P1，P3 使用下层公开能力；下层不依赖上层代码、运行时或模型。console 与实例平级，权限和运行隔离保持。
- 接口/契约是模块边界。跨语言需要明确协议及适配器；Go interface 本身不是跨语言 API。字段、金额/时间/未知、授权、幂等、超时和故障语义必须保持；不得直连下层私有实现/数据库或绕过执行与准入。
- 所有非敏感自有源码仍公开，按[文件树规范](REPOSITORY_LAYOUT.md)归位；私有 config/Prompt 规则保持。新增模块登记 manifest/lockfile、依赖、构建、测试与运行方式，不能误把现有 Go 检查当作覆盖所有语言。

## 为什么保护内部实现与数据库边界

“私有实现”是未承诺兼容的内部函数、类型和表结构，不是闭源；源码仍公开，可以阅读、参考和调试。限制的是把内部实现当成上层长期运行依赖，而非禁止查看源码，也不禁止模块访问自己负责的存储。

- 可替换性：公开契约把调用方与实现语言、包路径和表结构隔开；直接耦合内部实现会使下层重构或语言替换牵动上层。
- 规则完整性：交易写操作经统一入口核验风险、版本、幂等、所有权/epoch和审计。跨层直写表或绕过用例调用内部组件可能跳过这些步骤。
- 一致性与权限：直接读表也会绑定事务时点、schema、权限和未脱敏字段；接口负责提供可解释的快照、时间和有限 DTO。

接口不等于 HTTP。现有公开 DTO/client 与进程内端口可以继续使用，跨语言另行明确传输。公开 SDK、事件订阅或专用只读数据库视图也可以作为未来接口候选，但必须先在对应层设计中定义受支持的契约、授权、快照与兼容规则；本次没有批准新的数据库视图访问方式。原则是不得绕过正式边界，不是禁止一切数据库或代码复用。

## 本次范围与未定项

本次只放宽实现语言约束，四组业务式样、现有接口、公式、阶段与准入保持，按设计修订增加 PATCH 为 v2.1.15。选择语言不等于改变三层框架；未来若实际改变职责/依赖或功能/验收，仍按最高类别升版。

OMP 整体外挂、抽出 TypeScript 模块、Go 实现，以及辅助抽取器/模型/供应商都未选定。没有新增 API/官方登录双模式功能，没有指定 Node/Bun 为必需运行时；OAuth 可刷新凭据存放方式仍须设计，不擅自突破 config/config.toml 规则。后续照“试验验证并记录证据 → 完成对应设计 → 按设计实现”；涉及功能/效果/验收则先修订式样。

用户因主机负载暂停的 Ubuntu 本地模型实验继续停止；抽取实现由用户参与决策，本次不恢复或启用。已存在的未提交修复、试验代码和运行证据保留，不混入此次文档变更。
